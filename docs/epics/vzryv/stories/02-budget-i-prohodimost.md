# STORY 02 — Бюджет по уровням и проходимость в рамках бюджета

**Эпик:** Взрыв с лимитом зарядов
**Статус:** в работе

## Ценность

Игрок может **ощутить дефицит зарядов хотя бы на части из 7 уровней, оставаясь способным
пройти любой уровень**, чтобы взрыв воспринимался как **решение с ценой**, а не формальность,
и чтобы плейтест главной гипотезы VISION (мета-сборка компенсирует слабости ядра) был честным.

> Опирается на Стори 01 (счётчик, списание, no-op на нуле, HUD, чит уже работают на едином
> плейсхолдере). Эта стори заменяет плейсхолдер реальными числами per level и доказывает, что
> каждый уровень остаётся проходимым при своём бюджете.

## Критерии приёмки

- [ ] Каждому из 7 уровней задан **индивидуальный** бюджет зарядов в `LevelMap._levels`
  (не единый дефолт из Стори 01) — число отражает, сколько подчистки типично требует мишень
  уровня.
- [ ] Минимум на части уровней бюджет **ощутимо давит**: пройти уровень без права на лишний
  взрыв возможно только чистой укладкой, чрезмерный запас зарядов не выдан «про запас».
- [ ] Автотест **«каждый уровень проходим в рамках своего бюджета зарядов»** — для всех 7
  уровней: структурная проверка (бюджет ≥ 0, уровень в принципе решаем без взрыва сверх лимита)
  + минимум один реальный/детерминированный прогон через `GameController`, аналогично
  `level_playthrough_test.dart` из «Контента».
- [ ] Полный прогон (`win_flow_test`) обновлён и зелёный при выставленных бюджетах: сквозной
  сценарий всех 7 уровней подряд не падает из-за нехватки зарядов.
- [ ] `flutter analyze` — 0; все тесты зелёные.

## Не входит

- Изменение самих мишеней/масок уровней — заморожено (VISION, EPIC.md «Не входит»); бюджет
  подбирается **под существующий контент**, контент не меняется.
- «Красивый» визуал индикатора сверх функционального — эпик «Готовность к плейтесту».
- Балансировка по метрикам реального плейтеста, туториал, объяснение механики игроку —
  эпик «Плейтест» (#5).
- Ловушки как источник сложности — вне эпика (EPIC.md).

## Затронутые модули

- `lib/game_engine/data/` — `LevelMap._levels`: реальные числа бюджета зарядов per level
  (было: единый плейсхолдер из Стори 01).
- `test/` — новый тест «проходимость в рамках бюджета» (⚠ хрупкое: расчёт экономики), плюс
  обновление `win_flow_test.dart` под реальные бюджеты.

## Задачи

> Предварительная нарезка (AGENT.md п. 3); финализируется при старте стори.

### T1 — Подбор бюджета зарядов по 7 уровням
- **Статус:** готова
- **Модули:** game_engine/data (`LevelMap._levels`, новая таблица `_chargeBudgets`)
- **Результат (как проверить):** `_chargeBudgets = [2, 0, 0, 2, 2, 1, 0]` — каждый из 7 уровней
  получил своё число (не единый плейсхолдер 3 из Стори 01). Обоснование по форме мишени —
  в `level_map.dart` (doc-комментарий) и в «Заметках по выполнению» ниже. Fallback A→B НЕ
  сработал: контраст между уровнями есть (3 уровня — бюджет 0, реально не нужен взрыв;
  4 уровня — бюджет 1-2, реально неровная форма). `flutter analyze` — 0; `flutter test` — 274
  passed (без изменений в количестве — T1 не добавляет тестов, только числа).

## Заметки по выполнению

- **T1 завершён.** Бюджет per level (`_chargeBudgets` в `level_map.dart`), рассуждение по
  форме мишени `ShipParts.parts[i].mask` (контент не менялся):
  - **Уровни 1, 2** (верхний/нижний корпус, сплошной прямоугольник 4×3) и **6** (хвост,
    сплошной квадрат 2×2) — **бюджет 0**. Падение стандартных тетромино укладывает их без
    единого взрыва — это уже доказано реальным дропом ещё в «Контенте»
    (`test/game_engine/data/level_playthrough_test.dart`: 3×I для уровня 1, 1×O для уровня 6).
    Раз взрыв там объективно не нужен — не выдаём заряды «про запас» (прямое попадание в
    критерий приёмки «чрезмерный запас не выдан»).
  - **Уровень 5** (двигатель 4×2, `#### / .##.`) — **бюджет 1**. Нижний ряд уже верхнего
    (сужение по бокам): стандартная посадка тетромино легко перельёт блок за пределы `S` в `H`
    по краям нижнего ряда — один взрыв на подчистку типичен.
  - **Уровни 0** (нос 4×2, `.##. / ####`), **3 и 4** (крылья 3×3, ступенчатый треугольник) —
    **бюджет 2**. Самые неровные мишени: ни одна из 7 фигур не имеет footprint «1×N в одном
    ряду», а нижний/верхний ряды мишени разной ширины — точное совпадение с `S` без захвата
    `H` практически недостижимо чистым дропом, обычно нужна подчистка в 1-2 местах.
  - **Не строил солвер и не проверял вручную все раскладки** (по прецеденту «Контента»,
    Стори 02: там тоже осознанно ограничились 2 реальными прогонами из 7 + структурными
    проверками, полный солвер — отдельная комбинаторная задача вне бюджета задачи). Рассуждение
    выше — эвристика по форме, не формальное доказательство минимальной достаточности числа;
    если на T2 реальный прогон покажет, что бюджета не хватает даже при аккуратной игре —
    поднять число (это часть T2, не отдельная эскалация).
  - **Fallback A→B не сработал.** Контраст присутствует: не все уровни бюджет 0 (иначе — «взрыв
    не нужен нигде», сигнал к эскалации) и не все уровни одинаковый ненулевой бюджет (иначе —
    «дефицит не потюнить» тоже сигнал). 3 нулевых / 4 ненулевых с разной формой — осмысленный
    разброс.
