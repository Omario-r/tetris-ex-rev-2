# STORY 01 — Экономика зарядов, HUD-индикатор, дев-чит

**Эпик:** Взрыв с лимитом зарядов
**Статус:** в работе

## Ценность

Игрок может **видеть и тратить ограниченный запас зарядов взрыва за уровень**, чтобы
**подчистка краёв стала осмысленным выбором («уложить чисто или потратить заряд»), а не
бесплатным действием**, как требует VISION («взрыв держим простым: единственное усложнение —
лимит зарядов за уровень»).

> Точные числа бюджета по каждому из 7 уровней — **Стори 02**. Здесь бюджет — единое
> дефолтное значение (плейсхолдер), достаточное, чтобы проверить механику списания,
> читаемость HUD и дев-чит; тюнинг под конкретные мишени — следующим шагом.

## Критерии приёмки

- [ ] На старте уровня заряды сброшены к бюджету уровня; заряды **не переносятся** между
  уровнями и не копятся (новый `GameController`/уровень → полный бюджет).
- [ ] Каждый успешный `armExplosive()` тратит ровно 1 заряд.
- [ ] На нуле зарядов `armExplosive()` — **no-op** (по конвенции движка «невозможное действие =
  no-op»): заряд не взводится, партия продолжается обычным падением, победа всё ещё достижима
  чистой укладкой (без залёта в halo).
- [ ] HUD показывает остаток зарядов и явно отличимое состояние «зарядов нет» —
  **читается без слов** (кнопка/индикатор взрыва визуально меняется при 0, не только
  становится логически неактивной).
- [ ] Дев-чит-меню получает пункт «выставить число зарядов» (аналогично существующему
  «состояние корабля»), виден только под `kDebugMode`.
- [ ] `flutter analyze` — 0 ошибок и предупреждений; существующие тесты зелёные + новые тесты
  на экономику зарядов (списание, no-op на нуле, сброс на старте уровня).

## Не входит

- Подбор итоговых чисел бюджета по каждому из 7 уровней контента — **Стори 02**.
- Автотест «каждый уровень проходим в рамках бюджета» — **Стори 02**.
- Ловушки, прицел-риск, комбо, выбор точки взрыва — вне эпика (VISION-заморозка, см. EPIC.md).
- Сам эффект взрыва (радиус/что сносит) — не меняется, только когда его можно применить.
- «Красивый» визуал индикатора сверх функциональной читаемости — эпик «Готовность к плейтесту».

## Затронутые модули

- `lib/game_engine/models/` — поле бюджета зарядов на `LevelTemplate` (по аналогии с
  существующим опциональным `moveLimit?`); дефолт единый, пока не тюнингован (Стори 02).
- `lib/game_engine/game/` — `GameState` получает счётчик зарядов; `GameController.armExplosive`
  списывает заряд / no-op на нуле; сброс счётчика на старте партии/уровня.
- `lib/game_engine/data/` — `LevelMap._devLevels` передаёт бюджет в `LevelTemplate` (единый
  плейсхолдер для всех 7 уровней).
- `lib/presentation/widgets/` — `GameHud` — индикатор остатка + видимое disabled-состояние
  кнопки взрыва при 0.
- `lib/presentation/screens/` — `CheatMenu` — новый пункт «выставить заряды», колбэк в
  `GameScreen` → `GameController`.
- `test/` — тесты счётчика зарядов (game_engine/game), HUD-индикатора (presentation), чита
  (presentation).

## Задачи

> Предварительная нарезка (AGENT.md п. 3); финализируется при старте стори. Каждая задача
> держится в пределах правила трёх модулей.

### T1 — Экономика зарядов в состоянии партии
- **Статус:** готова
- **Модули:** game_engine/models (`LevelTemplate` — поле бюджета зарядов, дефолт-плейсхолдер),
  game_engine/data (`LevelMap._devLevels` — прокидывает бюджет), game_engine/game (`GameState` —
  счётчик; `GameController.armExplosive` — списание/no-op на нуле; сброс на старте уровня)
- **Результат (как проверить):** `flutter test test/game_engine/game/` — 47 тестов зелёные,
  включая новую группу «заряды (экономика взрыва)»: заряды на старте == `chargeBudget` уровня,
  `armExplosive` списывает 1 при заряде > 0, `armExplosive` на 0 — no-op (фигура остаётся
  `normal`, `armedUsed` не взводится, заряды не уходят в минус), новый `GameController`/уровень —
  заряды снова равны бюджету, `setCharges` (дев-чит, задел для T3) выставляет заряды напрямую.
  `flutter analyze` — 0; полный `flutter test` — 270 passed.

### T2 — HUD-индикатор зарядов
- **Статус:** готова
- **Модули:** presentation/widgets (`GameHud`), game_engine/game (`GameState` — источник данных
  для индикатора)
- **Результат (как проверить):** `flutter test test/presentation/hud_test.dart` — 6 тестов
  зелёные: числовой индикатор (`Key('charges_indicator')`) показывает `state.charges`, цвет
  белый при зарядах > 0 и `Colors.redAccent` на 0 (визуально иное состояние, не только
  disabled-флаг). Ручная проверка через Preview (`flutter run -d web-server` + скриншот,
  уровень 1) — индикатор «3» читается под кнопкой arm без пояснений. `flutter analyze` — 0;
  полный `flutter test` — 273 passed.

### T3 — Дев-чит «выставить число зарядов»
- **Статус:** не начата

## Заметки по выполнению

- **T1 завершён.** `LevelTemplate.chargeBudget` (дефолт 3) — новое поле по аналогии с уже
  существующим `moveLimit?`. `LevelMap` пока передаёт единый плейсхолдер `chargeBudget: 3` для
  всех 7 уровней (явно, с комментарием — тюнинг реальных чисел в Стори 02).
- **`GameState.charges` дефолтится от `level.chargeBudget`** через опциональный именованный
  параметр (`int? charges`) с вычисляемым значением в initializer list. Побочный эффект:
  конструктор `GameState` пришлось сделать НЕ `const` (вычисляемое значение из `level` —
  не константное выражение). Проверил перед правкой: `const GameState(...)` нигде по кодовой
  базе не вызывался (только объявление), так что снятие `const` безопасно, поведение не
  меняется.
- **`canArm` теперь также требует `charges > 0`** (в `GameState`, не в `GameController`) — HUD
  уже был завязан на `state.canArm` для видимого disabled-состояния кнопки arm (`Opacity`
  0.3/1.0 в `hud.dart`), поэтому визуальное затемнение при 0 зарядов заработало «бесплатно»,
  без правок `widgets`. T2 добавит только числовой индикатор остатка (затемнение само по себе
  не объясняет игроку «почему» — это и есть задача T2).
- **`GameController.setCharges(n)`** добавлен в T1 (не в T3), т.к. естественно ложится в тот же
  файл `game_controller.dart`, который и так менялся. T3 использует его для дев-чита, сам метод
  уже покрыт тестом здесь.
- **T2 завершён.** Индикатор — простой `Text('${state.charges}')` под кнопкой arm (в `Column`),
  цвет белый/`redAccent` по `charges > 0`. Затемнение самой кнопки (`Opacity` 0.3/1.0) уже
  работало из T1 через `canArm`, T2 добавил только число + цвет — так игрок видит, сколько
  осталось, а не только «недоступно». Скриншот через Preview (уровень 1, `flutter run -d
  web-server`) подтвердил: «3» читается чётко под иконкой крипера, без подписи.
