# STORY 01 — Прототип укладки (контрольная точка эпика)

**Эпик:** Укладка — новое ядро сборки детали
**Статус:** в работе (нарезана на T1–T3 2026-07-20)

> **Контрольная точка эпика.** После приёмки этой стори на Гейте 2 —
> **вердикт PO пальцами на устройстве**, а НЕ автоматический чейнинг к Стори 02.
> «Да» → пересаживаем ядро (Стори 02+); «нет» → эпик останавливается,
> потеряна одна стори, а не движок.

## Ценность

Пользователь (PO) может **собрать деталь корабля, перетаскивая кусочки-полиомино
из подачи в силуэт детали на прототип-экране (доступен из чит-меню), с тумблером
подачи «полный набор / лоток-3»**, чтобы **пальцами на устройстве вынести вердикт:
приятен ли акт точной укладки настолько, чтобы доводить новое ядро** (главная
гипотеза VISION).

## Критерии приёмки

> Проверяемые, конечный список. Визуальные/поведенческие критерии Постановщик
> прогоняет один раз на Гейте 2 (устройство/Preview).

- [ ] Из чит-меню открывается прототип-экран укладки (кнопка/пункт «Прототип
  укладки»); открытие не ломает существующие экраны.
- [ ] Кусочек перетаскивается из подачи в силуэт: валидное положение («полностью
  внутри силуэта» И «без пересечения с уже уложенными») — кусок ложится;
  невалидное — отбивается (возврат в подачу/исходную позицию), состояние не бьётся.
- [ ] Уже уложенный кусок можно вытащить и переложить в другое валидное место.
- [ ] Когда силуэт заполнен без дыр — прототип сигналит «деталь собрана»
  (видимый признак завершения).
- [ ] Тумблер подачи в чит-меню переключает режим: «полный набор на виду» ↔
  «порционный лоток-3»; поведение подачи меняется соответственно и переживает
  перезаход на прототип-экран.
- [ ] **Генератор нарезки** (автотесты `flutter test`): для набора тестовых масок
  нарезка покрывает силуэт **полностью, без дыр и пересечений**; каждый кусок —
  **3–5 клеток**; распределение размеров **не вырождается в россыпь доминошек/
  уголков** (проверяемый порог на долю мелких кусков — конкретизируется в ТЗ).
- [ ] `flutter analyze` — ноль ошибок и предупреждений; `flutter test` — зелёный.

- **Детерминизм генератора:** нарезка должна быть тестируемой с сидом (как

- **Чит-меню** (`presentation/screens/cheat_menu.dart`) — точка входа тумблера
  подачи и кнопки прототипа; VISION требует, чтобы чит-меню жило и в новом ядре.
- Укладка-движок и генератор — фрагменты для автотестов (VISION: «логику укладки
  и генератор нарезки покрываем автотестами»); генератор — хрупкий алгоритмический

  - `pack_piece.dart` — `PackPiece`:
    - поля: `final int id;` `final List<({int x, int y})> cells;` — локальные
      клетки кусочка (нормализованные: `min x == 0`, `min y == 0`), связные по

    - `int get size => cells.length;`
    - конструктор `const PackPiece({required this.id, required this.cells});`
    - `///`-комментарии на публичном API.
  - `pack_state.dart` — `PackState` (иммутабельный снапшот):
    - `final TargetMask silhouette;` — целевой силуэт S (в его локальных коорд.).
    - `final Map<int, ({int x, int y})> placements;` — `pieceId → origin`
      (левый-верх кусочка в координатах силуэта); только уложенные.
    - `final List<PackPiece> pieces;` — полный набор кусочков нарезки (по `id`).
    - `final List<int> trayOrder;` — id кусочков, ещё не уложенных (порядок лотка).
    - геттер `Set<({int x, int y})> occupiedCells` — все клетки, покрытые
      уложенными кусочками (клетка кусочка + origin).
    - геттер `bool get isComplete` — **все** клетки `silhouette.cells` покрыты и
      покрытий-пересечений нет (каждая клетка силуэта занята ровно одним кусочком,
      уложены все нужные) ⇒ «деталь собрана».
    - `PackState copyWith({...})`.
  - `pack_controller.dart` — `PackController`:
    - `PackController(PackState initial);` `PackState get state;`
    - `void place(int pieceId, int atX, int atY)` — уложить кусочек из лотка в
      позицию `origin=(atX,atY)`. Применяется, только если `canPlace` (ниже),
      иначе **no-op** (исключений НЕ бросать — как `GameController`). Убирает id
      из `trayOrder`, добавляет в `placements`.
    - `void move(int pieceId, int atX, int atY)` — переложить уже уложенный
      кусочек в новую позицию; валидация та же (пересечение считать против
      ОСТАЛЬНЫХ уложенных, не считая сам кусочек). no-op при невалидности.
    - `void remove(int pieceId)` — снять уложенный кусочек обратно в лоток
      (в конец `trayOrder`). no-op, если не уложен.
    - валидация (можно вынести в `pack_rules.dart` статиком или в контроллер —
      на усмотрение Исполнителя, но чистая функция):

      = **каждая** клетка кусочка `(atX+cx, atY+cy)` входит в `silhouette`
      (`silhouette.contains`) И не пересекается с `occupiedCells` уложенных
      (кроме `ignoreId`). Кусочек целиком внутри силуэта и без наложений.

### T2 — Генератор нарезки силуэта (slicer) + автотесты распределения

- **Статус:** не начата
- **Рекомендованный агент:** Исполнитель (**тяжёлая**) · Claude Opus

  распределения).
- **Цель:** детерминированный генератор, режущий силуэт `TargetMask` на связные
  полиомино-кусочки по 3–5 клеток, покрывающие S полностью и без пересечений
  (решение существует по построению — генератор его строит), с тюнингом
  распределения размеров, чтобы нарезка не вырождалась в россыпь мелочи.
- **Модули (≤ 3):** `lib/game_engine/packing/` (паспорт:
  `lib/game_engine/packing/README.md`) — добавляется файл нарезки; читает
  `lib/game_engine/models/` (`TargetMask`). Использует `PackPiece` из T1.
- **Что сделать:** `lib/game_engine/packing/pack_slicer.dart`, чистый Dart:
  - API: `List<PackPiece> slicePolyomino(TargetMask silhouette, {int? seed});`
    возвращает кусочки с уникальными `id` (0..N-1), нормализованными `cells`
    (как требует `PackPiece`), покрывающие **все** клетки `silhouette.cells`,
    попарно непересекающиеся, каждый — 3..5 клеток, связный по 4-соседству.
  - Детерминизм: при одном `seed` — идентичная нарезка (для воспроизводимых
    тестов; как `SevenBagGenerator(seed)`). `seed == null` — случайная.
  - Алгоритм (ориентир, финал — за Исполнителем): выращивание кусочков из
    случайной стартовой клетки по 4-соседству до случайного целевого размера
    3..5 в пределах оставшихся клеток S; при риске отрезать «хвост» < 3 клеток —
    добор соседних/бэктрекинг, чтобы каждый финальный кусок был 3..5. Гарантия
    завершимости: любой связный полиомино из ≥3 клеток разбивается на куски 3..5
    (n = сумма троек/четвёрок/пятёрок для любого n≥3); реализовать так, чтобы
    генератор не застревал (бэктрекинг/повторная попытка с тем же seed-потоком).
  - Тюнинг распределения: смещать целевой размер к 4–5, а не к 3, чтобы доля
    3-клеточных кусков была ограничена. Конкретный порог — в критерии теста ниже.
  - Предусловие/грань: `silhouette.cells.length >= 3` и силуэт связен (все наши
    маски таковы). Для несвязного/крошечного силуэта поведение задокументировать
    (напр. `assert` + пустой/частичный результат) — но игровые силуэты валидны.
  - **Автотесты** `test/game_engine/packing/pack_slicer_test.dart` — для набора
    масок: `defaultTargetMask` (крест 6×6, `game_engine/models/target_mask.dart`)
    и 2–3 маски деталей из `game_engine/data/ship_parts.dart` (напр. верхний
    корпус 4×3 `0xFFF`, нос 4×2 `0x6F`, двигатель 4×2 `0xF6`):
    - покрытие: `union(cells+origin по всем кускам) == set(silhouette.cells)`;
    - непересечение: сумма размеров == число клеток силуэта;
    - размеры: каждый кусок 3..5; связность каждого куска (4-соседство);
    - детерминизм: `slice(m, seed: 1)` дважды даёт идентичный результат;
    - **распределение** (антивырождение): на большом силуэте (крест 6×6 = 20
      клеток) доля кусков размера 3 — не выше порога (ориентир: **≤ 50%** кусков
      размера 3; должен присутствовать хотя бы один кусок размера ≥ 4). Точный
      порог Исполнитель фиксирует так, чтобы тест был стабилен на нескольких
      seed'ах, и комментирует выбор.
- **Арх-дельта:** нет (тот же модуль `packing`, новых модулей/связей нет; паспорт
  модуля обновляет Исполнитель — добавить `slicePolyomino` в публичный интерфейс).
- **Дизайн-референс:** нет (чистое ядро).
