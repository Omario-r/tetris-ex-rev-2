# STORY 03 — Адаптация контента, тестов и чистка

**Эпик:** Укладка — новое ядро сборки детали
**Статус:** не начата

> **Условна.** Идёт после Стори 02 (ядро уже пересажено). Завершает эпик:
> контент проходится на новом ядре, проект чист и без зомби-кода.

## Ценность

Пользователь может **пройти весь дев-контент корабля на новом ядре укладки
(каждый уровень-деталь собирается, полный прогон до собранного корабля)**, чтобы
**эпик закрывался на зелёном, воспроизводимом проекте без остатков старого ядра**.

## Критерии приёмки

- [ ] Каждая дев-деталь (`data/ship_parts`) собирается на новом ядре: её маска
  силуэта нарезается генератором и укладывается до заполнения без дыр (маски и
  материалы переиспользованы как есть — без переделки контента).
- [ ] Сквозной смоук-сценарий переписан под укладку: полный прогон всех уровней
  контента до собранного корабля и финал-сброса проходит автотестом (аналог
  `win_flow_test` эпика «Контент», адаптированный под новое условие победы).
- [ ] Мёртвый код удалён: `lib/game_engine/rules/rotation.dart` (пустой TODO),
  `lib/application/game_loop.dart` (`GameLoop`-стуб), любые оставшиеся после
  Стори 02 хвосты взрыва/падения. `grep` по проекту не находит зомби-вызовов.
- [ ] `docs/ARCHITECTURE.md`, паспорта затронутых модулей и смоук-команда
  (`PROJECT.md` / ARCHITECTURE «Команды и смоук-тест») обновлены под новое ядро.
- [ ] `flutter analyze` — 0; `flutter test` — зелёный; смоук-команда проекта
  проходит.

## Не входит

- Новые фичи ядра (вращение, лоток-настройки сверх тумблера, бустеры) — рычаги
  после плейтеста (VISION).
- Дизайн-канон / полировка визуала — вне этого эпика (см. Стори 02 открытый вопрос).
- Новая иконка приложения, звёзды/пар, монетизация — BACKLOG/после плейтеста.
- Развязка `models`↔`rules` взаимозависимости — отдельная уборка (BACKLOG),
  не тащим в этот эпик, если ядро её не потребует по ходу.

## Контекст для нарезки

- **Контент переиспользуется как есть** (EPIC.md): маски силуэтов и материалы не
  перерисовываются; задача — убедиться, что каждый существующий силуэт
  *нарезаем и укладываем* новым ядром (генератор Стори 01), и переписать сквозной
  тест под новое условие победы «силуэт заполнен без дыр».
- **Смоук эпика «Контент»:** `test/presentation/win_flow_test.dart` — полный
  прогон всех уровней до собранного корабля (эпик «Контент», Стори 03). Здесь его
  логику победы надо перевести с halo/взрыва на укладку. `test/widget_test.dart` —
  пустая заглушка (BACKLOG); при обновлении смоук-команды учесть.
- **Мёртвый код — давние кандидаты** (BACKLOG 2026-07-07): `rules/rotation.dart`,
  `application/game_loop.dart`. Эпик прямо называет их попутными кандидатами при
  выпиле. Удалять только то, что после Стори 02 действительно не подключено.
- **Фикстура тестов движка:** `defaultLevel` (крест 6×6, маска `0x30CFFF30C`) —
  НЕ игровой уровень, тесты движка на нём; не удалять при чистке (ARCHITECTURE).
- Зависит от Стори 02 (ядро уже в `game_screen`, старое ядро выпилено).
