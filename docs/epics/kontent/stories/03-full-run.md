**Эпик:** Контент: узнаваемый корабль
**Статус:** на приёмке (Гейт 2) — реализована 2026-07-08

## Ценность

Игрок может **за один прогон пройти все 6–8 уровней подряд и увидеть цельный собранный корабль**
(а затем начать заново), чтобы **меты хватало дожать корабль до конца** (VISION успех №3:
«игрок доходит до полной сборки хотя бы в одном прогоне»).

> Поток победы и финал-сброс уже завязаны на `kShipPartCount-1` (Мета-каркас). После Стори 01
> `kShipPartCount` = 6–8, поэтому стори по большей части **верифицирует и покрывает тестом**
> полный прогон, а не строит логику заново.

## Критерии приёмки

- [x] Поток победы масштабируется на N: победа на уровне `i` (`i < N-1`) → экран корабля с `i+1`
  деталями + «Далее» → уровень `i+1`; так до последнего.
  _Доказано: `win_flow_test.dart` — новый тест «полный прогон»: цикл по всем 7 уровням читом
  «мгновенная победа», на каждом шаге проверено «Собрано i+1 из 7» + правильный переход
  levelIndex. Уже был готов из Стори 01/02 (`kShipPartCount` везде производный) — код не менялся,
  только тест._
- [x] Победа на **последнем** уровне (индекс `kShipPartCount-1`) → экран **собранного корабля N/N**
  + «Начать заново» → `ProgressService.reset()` → уровень 0.
  _Доказано: тот же тест «полный прогон» — на последней (7-й) итерации «Собрано 7 из 7» +
  «Начать заново» → `GameScreen(levelIndex: 0)`, `getCurrentLevel() == 0`._
- [x] Прогресс сборки растёт и **сохраняется между запусками** до N (кламп `min(current_level,
  kShipPartCount)`).
  _Доказано: уже покрыто `ship_screen_test.dart` (Стори 01) — параметризованный тест
  `min(current_level, 7)` для current_level ∈ {0,1,2,3,5,7,15} + отдельный тест
  «повторное открытие показывает то же число деталей»._
- [x] Чит-меню предлагает **выбор всех N уровней** и состояние корабля 0..N.
  _Доказано: состояние корабля — уже было (Стори 01). Выбор уровней — добавлен новый тест
  `cheat_menu_test.dart` «предлагает ровно kShipPartCount уровней»: все 7 индексов присутствуют,
  индекс `kShipPartCount` (8-й, за границей) отсутствует._
- [x] _(смоук)_ Сквозной тест **полного прогона**: собрать все N уровней
  (`FixedSequenceGenerator`/чит) → на каждом деталь +1 → финал N/N → «Начать заново» → уровень 0.
  _Доказано: `win_flow_test.dart` — «полный прогон (Стори 03, смоук)». `ARCHITECTURE.md`
  обновлён: смоук-команда включает `test/presentation/win_flow_test.dart`._
- [x] `flutter analyze` — ноль; все тесты зелёные (`flutter test`).
  _Доказано: `flutter analyze` — No issues found; `flutter test` — 263 passed._

## Заметки по выполнению

- **Почти вся стори — верификация, не разработка** (как и предполагалось при декомпозиции):
  Стори 01 сделала `kShipPartCount` производным от `ShipParts.parts.length`, поэтому поток
  победы (`game_screen._onWin`/`_afterShipReveal`), чит «состояние корабля» и клампы в
  `ship_screen`/`ship_painter` уже работали на N=7 без единой правки кода в этой стори.
- **`ProgressService._max=15` — сознательно не менял.** Разобрал: `advanceOnWin`/`setCurrentLevel`
  клампят `current_level` в 0..15 (наследие старой карты 16 уровней). Т.к. поток победы сам
  вызывает `reset()` при достижении последнего дев-уровня (индекс `kShipPartCount-1`) ДО того,
  как `current_level` успевает вырасти за пределы N, значение 15 никогда не достигается на
  практике при N=7 — кламп безвреден, просто устаревшее магическое число. Чинить не стал:
  `ProgressService` (application) не должен импортировать `kShipPartCount`
  (`presentation/widgets`) — это нарушило бы направление импортов (ARCHITECTURE: только вниз);
  переносить константу в `game_engine/data` ради этого — рефакторинг вне границ стори
  (много вызывающих мест). Оставил как есть; при желании — отдельная уборка на инвентаризации.
- **Пробел в чите нашёл и закрыл.** `cheat_menu_test` проверял только что кнопка уровня 2
  существует (`cheat_level_2`) — не проверял, что уровней РОВНО N (не больше, не меньше).
  Добавил тест на границу: индексы 0..6 есть, индекс 7 (за `kShipPartCount`) — нет.
- **Смоук-тест был мёртвым.** `test/widget_test.dart` (первый файл в смоук-команде
  ARCHITECTURE.md) — пустая заглушка (`// TODO`), ничего не проверяет уже давно. Не стал чинить
  в рамках этой стори (не входит в её критерии) — записал в `BACKLOG.md`. Вместо этого добавил
  в смоук-команду `win_flow_test.dart`, где теперь живёт содержательный полный прогон —
  это и есть проверка «главного сценария» для контента (VISION успех №3).
