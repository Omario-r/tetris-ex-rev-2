**Эпик:** Контент: узнаваемый корабль
**Статус:** не начата

## Ценность

Игрок может **за один прогон пройти все 6–8 уровней подряд и увидеть цельный собранный корабль**
(а затем начать заново), чтобы **меты хватало дожать корабль до конца** (VISION успех №3:
«игрок доходит до полной сборки хотя бы в одном прогоне»).

> Поток победы и финал-сброс уже завязаны на `kShipPartCount-1` (Мета-каркас). После Стори 01
> `kShipPartCount` = 6–8, поэтому стори по большей части **верифицирует и покрывает тестом**
> полный прогон, а не строит логику заново.

## Критерии приёмки

- [ ] Поток победы масштабируется на N: победа на уровне `i` (`i < N-1`) → экран корабля с `i+1`
  деталями + «Далее» → уровень `i+1`; так до последнего. _(Проверка: пройти подряд читом
  «мгновенная победа».)_
- [ ] Победа на **последнем** уровне (индекс `kShipPartCount-1`) → экран **собранного корабля N/N**
  + «Начать заново» → `ProgressService.reset()` → уровень 0 (переиспользуем финал-сброс
  Мета-каркаса). _(Проверка: пройти последний уровень → «Собрано N из N» → «Начать заново» →
  уровень 1, `current_level == 0`.)_
- [ ] Прогресс сборки растёт и **сохраняется между запусками** до N (кламп `min(current_level,
  kShipPartCount)`). _(Проверка: собрать k деталей, перезапустить → экран корабля показывает k.)_
- [ ] Чит-меню предлагает **выбор всех N уровней** и состояние корабля 0..N.
- [ ] _(смоук)_ Сквозной тест **полного прогона**: собрать все N уровней
  (`FixedSequenceGenerator`/чит) → на каждом деталь +1 → финал N/N → «Начать заново» → уровень 0.
  Обновить смоук-команду в `ARCHITECTURE.md`, если состав файлов сменился.
- [ ] `flutter analyze` — ноль; все тесты зелёные (`flutter test`).

## Не входит

- Финал-фанфары/анимации/звук/частицы «корабль собран» — только статичный собранный корабль +
  сброс (как в Мета-каркасе).
- Визуальный стиль/скины — эпик «Плейтест-сборка».
- Формы, размещение и порядок мишеней — Стори 01/02.
