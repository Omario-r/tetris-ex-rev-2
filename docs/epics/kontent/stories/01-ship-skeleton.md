# STORY 01 — Скелет корабля: 6–8 деталей в единый силуэт

> Заполняет агент при декомпозиции эпика. PO утверждает на Гейте 1 и принимает
> на Гейте 2. Работа по стори НЕ начинается, пока секция «Открытые вопросы к PO»
> не пуста.

**Эпик:** Контент: узнаваемый корабль
**Статус:** принята (Гейт 2 пройден 2026-07-08)

## Ценность

Игрок может **открыть экран корабля и увидеть цельный узнаваемый силуэт из 6–8 деталей**
(а не 3 заглушки-прямоугольника), чтобы **понимать, что именно он собирает — «мой корабль»
как единую вещь** (VISION: «одна вещь — один корабль из ~10–12 деталей», v1 = первые 6–8;
успех №2/№3).

## Критерии приёмки

> Проверяемые, конечный список. По ним PO принимает стори на Гейте 2.

- [x] `ShipParts.parts` содержит **7 реальных деталей** (не 3 заглушки; анатомия — см.
  «Открытые вопросы»); их якоря (`shipX/shipY`) раскладывают детали в **один связный силуэт** —
  без наложений и без разрывов.
  _Доказано: `ship_parts.dart` — 7 деталей (нос/корпус×2/крылья×2/двигатель/киль), `gridSize=12`;
  тесты `ship_parts_test` «детали не накладываются» и «связный силуэт (4-связность)» зелёные;
  ASCII-рендер силуэта сверен глазами._
- [x] `kShipPartCount` **выводится из `ShipParts.parts.length`** (хардкод «3» убран); экран
  корабля, `ShipPainter`, читы «состояние корабля» и «выбор уровня» работают на новом числе
  без правок логики.
  _Доказано: `final int kShipPartCount = ShipParts.parts.length` (`ship.dart`); `cheat_menu`
  `levelCount` → `parts.length`; тест «kShipPartCount == parts.length» зелёный; `cheat_menu_test`
  показывает состояние 0..7, `ship_screen_test` — «min(current_level, 7)»._
- [x] `ShipPainter` рисует **весь корабль по центру и в масштабе**: силуэт помещается в сетку
  `ShipParts.gridSize`, детали не обрезаны.
  _Доказано: пейнтер масштабирует по `gridSize` и центрирует (код без правок — уже gridSize-driven);
  силуэт 12×12 вписан в сетку 12; `ship_screen_test` зелёный._
- [x] Собранный вид (все детали залиты) **читается как узнаваемый космический корабль** по
  утверждённой на Гейте 1 анатомии (нос/корпус/крылья/двигатель).
  _Доказано частично: силуэт соответствует анатомии Гейта 1 (ASCII-рендер: нос→кабина→корпус→
  расходящиеся крылья→двигатель→сопло). **Финальный визуальный вердикт — за PO** на устройстве/
  симуляторе (формы прототипные, шлифуются по скриншотам — см. «Открытые вопросы»)._
- [x] `flutter analyze` — ноль ошибок и предупреждений; существующие тесты обновлены под новое
  число деталей и зелёные.
  _Доказано: `flutter analyze` — No issues found; `flutter test` — 225 passed (было 216)._

## Не входит

- Проходимость мишеней на игровом поле, размещение и порядок уровней — **Стори 02**.
- Полный прогон подряд до собранного корабля и финал-сброс на N деталей — **Стори 03**.
- Визуальный стиль/скины/цвета/воксельная фактура — эпик «Плейтест-сборка».
- Любые изменения правил ядра (укладка, условие победы, halo) — заморожено VISION.

## Затронутые модули

> По карте из ARCHITECTURE.md.

- `lib/game_engine/data/` — `ship_parts` (6–8 реальных масок + якоря раскладки; при необходимости
  `gridSize`). Единый источник формы: `parts[i].mask` = мишень уровня и деталь корабля.
- `lib/presentation/widgets/` — `ship.dart` (`kShipPartCount` из `parts.length`; центрирование
  и масштаб `ShipPainter` под новый силуэт).
- `lib/presentation/screens/` — `ship_screen`/`cheat_menu` (клампы и `levelCount` уже идут через
  `kShipPartCount` — проверить, что не осталось хардкода «3»).

## Открытые вопросы к PO

_нет_ — закрыто PO на Гейте 1 (2026-07-08): **N = 7 деталей**, порядок сборки
`нос/кабина → верхний корпус → нижний корпус → левое крыло → правое крыло →
двигатель-сопло → хвостовой киль`; силуэт «звездолёт с крыльями». Точные формы масок
шлифуются при реализации по скриншотам (как в Мета-каркасе, Стори 03 T4).

## Задачи

> Предварительная нарезка (AGENT.md п. 3); финализируется при старте стори. Проект остаётся
> рабочим после каждой задачи (смоук-фикстура `defaultLevel` не трогается).

### T1 — 7 деталей в `ShipParts` + `kShipPartCount` из `parts.length` (единой правкой)
- **Статус:** готова
- **Модули:** game_engine/data (`ship_parts`), presentation/widgets (`ship.dart`),
  presentation/screens (`cheat_menu` — снятие const-дефолта; `game_screen` — комментарий) + тесты
- **Результат (как проверить):** экран корабля показывает 7 деталей связным силуэтом;
  `kShipPartCount == ShipParts.parts.length`; чит 0..7 и выбор 7 уровней; `flutter analyze` —
  No issues; `flutter test` — 225 passed.

> **T2 (центрирование/масштаб `ShipPainter`) — свёрнут в T1:** пейнтер уже gridSize-driven
> (масштаб/центр по `ShipParts.gridSize`), отдельной правки не потребовалось — только `gridSize`
> 10→12 в данных.

## Заметки по выполнению

- **Одной связной правкой (а не T1+T2):** смена числа деталей жёстко связана — `final
  kShipPartCount = ShipParts.parts.length` не `const`, поэтому дефолт `CheatMenu.levelCount =
  kShipPartCount` пришлось убрать (сделан nullable, резолв `?? kShipPartCount` в рантайме),
  иначе не компилируется. Та же смена ломает тесты с хардкодом «из 3» — их правил тем же заходом.
- **Правило «кратно 4» снято** (VISION, эпик «Контент»): удалён тест «площадь кратна 4»,
  заменён на «площадь ≥ 4». Детали корабля v1 имеют площади 6/12/12/6/6/6/4.
- **Границы дев-уровней 3→7:** `LevelMap._devLevels` авто-выводится из `ShipParts.parts.length`,
  правок `level_map.dart` не потребовалось; поправлен лишь тест `levelAt(4)` (стал дев-уровнем,
  граница со старой картой объектов сдвинулась на индекс 7). Ретайр старой карты — Стори 02.
- **Поток победы/финал** уже завязан на `kShipPartCount-1` — масштабировался сам (последний
  уровень стал индексом 6); `win_flow_test` обновлён под 7/7.
- **Силуэт** сверен ASCII-рендером (временный тест, удалён): нос(0)→кабина→корпус(1)→крылья(3/4)→
  корпус(2)→двигатель(5)→сопло(6), симметричный связный «звездолёт». Финальный вид — за PO
  (скриншот на устройстве); формы шлифуются по скриншотам.
