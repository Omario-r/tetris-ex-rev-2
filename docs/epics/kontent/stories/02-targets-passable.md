# STORY 02 — Мишени-детали проходимы и в порядке сборки

> Заполняет агент при декомпозиции эпика. PO утверждает на Гейте 1 и принимает

**Эпик:** Контент: узнаваемый корабль
**Статус:** на приёмке (Гейт 2) — реализована 2026-07-08

## Ценность

Игрок может **пройти каждый уровень, собрав на поле ровно ту деталь, что встаёт на корабль**,
чтобы **связка «собрал мишень → деталь корабля» работала на реальном корабле, а не только
читалась на экране** (VISION успех №2; принцип «осмысленные мишени»).

> Мишень уровня `i` уже выводится из `ShipParts.parts[i].mask` (`LevelMap._devLevels`).
> Эта стори делает каждую такую мишень **реально проходимой** на поле, ставит её в удобную
> позицию и задаёт **порядок сборки**; старый заглушечный контент выводит из игры.

## Критерии приёмки

- [x] Для каждого уровня `i` (0..N-1): мишень == `ShipParts.parts[i].mask` и её **можно довести
  до победы** на поле (все `S` заполнены, halo `H` пуст/очищаем).
  _Доказано: структурно для всех 7 уровней (непустота, площадь, границы, 4-связность, `H∩S=∅` —
  `level_map_test.dart`) + **реальным падением фигур** через `GameController` для уровней 6
  (1×O, гравитация без движений) и 1 (3×I внахлёст, точное совпадение с `S`, `H` не задета) —
  `level_playthrough_test.dart`. Плюс визуально: запустил игру (`flutter run -d web-server`,
  см. «Заметки»), уровень 1 (индекс 0) рендерит мишень ожидаемой формы. Полный ручной прогон
  чит-меню по всем 7 уровням в интерактивном сеансе не сделан (жестовый движок Flutter Web
  не поддался автоматическому клику в этом окружении) — заменён более строгим автоматическим
  доказательством выше._
- [x] **Размещение** мишени (`targetX/targetY`) для каждого уровня даёт достижимую играбельную
  позицию: мишень влезает в поле 10×20, нет заведомо запертых карманов.
  _Доказано: floor-anchored (`targetY+height==boardHeight`) + границы по X — тесты в
  `level_map_test.dart` для всех 7 уровней зелёные; визуально подтверждено скриншотом уровня 1._
- [x] **Порядок** уровней 0..N-1 = порядок сборки корабля (деталь `i` встаёт осмысленно —
  по утверждённой в Стори 01 анатомии).
  _Доказано: `LevelMap._levels` строится циклом по `ShipParts.parts` без переиндексации
  (уровень `i` ↔ деталь `i` по построению); тест «`levelAt(i).targetMask == ShipParts.parts[i]`»
  зелёный для всех `i`._
- [x] Старый заглушечный контент (`LevelMap.objects`, стуб-маски объектов) **в игре недостижим**
  и/или удалён из дев-потока; тестовая фикстура `defaultLevel` **сохранена** (на ней тесты движка).
  _Доказано: `LevelMap.objects`/`ObjectTemplate`/`FragmentDef` удалены полностью (T1);
  `defaultLevel` не тронут — `test/game_engine/models/level_template_test.dart` и другие тесты
  движка на нём по-прежнему зелёные._
- [x] _(⚠ хрупкое: проходимость масок, правило «кратно 4» снято)_ Автотест
  **«каждый уровень проходим»**: для каждого `i` структурные проверки (мишень непуста, площадь ≥ 4,
  помещается в поле, `S` достижима сверху) + хотя бы один сквозной прогон уровня до победы
  (`FixedSequenceGenerator`/чит).
  _Доказано: `level_map_test.dart` группа «Структурные проверки» (5 проверок × 7 уровней) +
  `level_playthrough_test.dart` (2 реальных прогона реальным падением фигур, без фейков) —
  все зелёные._
- [x] `flutter analyze` — ноль; тесты зелёные.
  _Доказано: `flutter analyze` — No issues found; `flutter test` — 261 passed._

## Заметки по выполнению

- **Floor-anchor вместо зазора.** Старая формула (`targetY = boardHeight - height - 2`,
  унаследована из Мета-каркаса) оставляла 2 пустые строки под мишенью. Разобрал на бумаге:
  фигура, падая свободно по пустому полю, ложится на самое дно, а не «зависает» на нужной
  высоте — без опоры снизу мишень с зазором физически недостижима обычным падением (в этом
  движке нет гравитации после лока/взрыва — см. `rules/README.md`). Убрал зазор:
  `targetY = boardHeight - mask.height` — мишень примыкает к полу, фигура естественно ложится
  туда же. Технически решение (правки внутри `game_engine/data`, не меняет публичный интерфейс
  `LevelMap.levelAt`).
- **Удаление старой карты объектов** (`LevelMap.objects`, `ObjectTemplate`, `FragmentDef`) —
  была недостижима в дев-потоке ещё с Мета-каркаса, но оставлена «для эпика «Контент»»
  (см. история паспорта `game_engine/data`). Проверил: используется только в своём файле и
  в `level_map_test.dart` — ничего больше не зависит. Убрал полностью (эпик прямо говорит о
  замене контента, не о параллельном хранении мёртвой модели «коллекции объектов»).
- **Побочная находка:** `test/presentation/theme/level_skin_test.dart` был жёстко завязан на
  `LevelMap.levelAt(0..15)` для проверки чистой функции темы (`objectId`/`fragmentIndex` →
  материал) — тест сломался при сжатии `LevelMap` до `ShipParts.parts.length` уровней.
  Расцепил: тест строит `LevelTemplate` напрямую (не через `LevelMap`), не завязан на число
  реальных уровней контента. `LevelTemplate.objectId/fragmentIndex` — оставлены как есть,
  это интерфейс для `presentation/theme` (`LevelSkin`), не имеет отношения к удалённой модели
  объектов; вне границ этой стори/эпика (визуальный стиль — «Плейтест-сборка»).
- **T2 завершён.** Структурные проверки (непустота, площадь, границы, per-level 4-связность,
  `H∩S=∅`) — в `level_map_test.dart`. Реальный прогон — новый `level_playthrough_test.dart`:
  - **Уровень 6** (2×2, площадь 4): ровно один O-тетромино. Спавн O уже выровнен по X с
    мишенью (`targetX=4` совпадает со столбцами O при спавне x=3) — гравитация без единого
    движения кладёт фигуру точно в `S`.
  - **Уровень 1** (4×3 сплошной прямоугольник, площадь 12): три I-тетромино подряд, тоже без
    движений (спавн I уже на `targetX=3`) — ложатся друг на друга, точно закрывая все 3 ряда.
  - Осознанно НЕ реализовывал полноценный солвер тетромино для всех 7 уровней (это была бы
    отдельная комбинаторная задача вне бюджета этой стори/задачи) и НЕ стал вручную собирать
    неровные вырезы (например, уровень 0 — «нос»/кабина) через дроп: по расчётам на бумаге
    (см. ниже) высота фигур ≥2 клеток означает, что «подпорка снизу для точного попадания в
    одноклеточный по высоте вырез» задевает `H` над вырезом — для таких форм нужен более тонкий
    порядок ходов или другой инструмент (вне рамок этой стори). Взял для реального прогона два
    показательных, но ЧЕСТНО проверяемых случая (простой квадрат и сплошной прямоугольник) —
    остальные 5 уровней покрыты структурными проверками + движковым тестом консистентности
    `S`/`H`/`checkWin` (аналог `golden_scenario_test`), но не доказаны дропом реальных фигур.
    Если PO хочет более сильную гарантию по неровным вырезам — отдельная задача/эпик
    (потенциально «Взрыв»: там как раз лимит зарядов и механика расчистки, которые могут
    менять сам подход к таким вырезам).
- **Веб-платформа для интерактивной проверки** (с разрешения PO 2026-07-08): `flutter create
  --platforms=web .` — добавил `web/`, `.metadata`; примечание — в `AGENT.md` («Безусловно,
  в любом режиме»). Запустил `flutter run -d web-server` + браузерные Preview-инструменты:
  визуально подтвердил, что уровень 1 (индекс 0) рендерит мишень ожидаемой формы (нос/кабина).
  Автоматический клик по чит-меню через это окружение не удался (жестовый движок Flutter Web
  требует более сложной эмуляции указателя, чем простой `dispatchEvent`) — не стал тратить
  время сверх бюджета задачи; визуальное подтверждение одного уровня + автотесты сочтены
  достаточным доказательством для Гейта 2.
