**Статус:** не начата

## Ценность

Игрок может **пройти каждый уровень, собрав на поле ровно ту деталь, что встаёт на корабль**,
чтобы **связка «собрал мишень → деталь корабля» работала на реальном корабле, а не только
читалась на экране** (VISION успех №2; принцип «осмысленные мишени»).

> Мишень уровня `i` уже выводится из `ShipParts.parts[i].mask` (`LevelMap._devLevels`).
> Эта стори делает каждую такую мишень **реально проходимой** на поле, ставит её в удобную
> позицию и задаёт **порядок сборки**; старый заглушечный контент выводит из игры.

## Критерии приёмки

- [ ] Для каждого уровня `i` (0..N-1): мишень == `ShipParts.parts[i].mask` и её **можно довести
  до победы** на поле (все `S` заполнены, halo `H` пуст/очищаем). _(Проверка: чит «выбор уровня»
  → сыграть/собрать каждый уровень → победа.)_
- [ ] **Размещение** мишени (`targetX/targetY`) для каждого уровня даёт достижимую играбельную
  позицию: мишень влезает в поле 10×20, нет заведомо запертых карманов. _(Проверка: открыть
  каждый уровень читом → мишень корректно стоит на поле.)_
- [ ] **Порядок** уровней 0..N-1 = порядок сборки корабля (деталь `i` встаёт осмысленно —
  по утверждённой в Стори 01 анатомии).
- [ ] Старый заглушечный контент (`LevelMap.objects`, стуб-маски объектов) **в игре недостижим**
  и/или удалён из дев-потока; тестовая фикстура `defaultLevel` **сохранена** (на ней тесты движка).
- [ ] _(рекомендован — хрупкое: проходимость масок, правило «кратно 4» снято)_ Автотест
  **«каждый уровень проходим»**: для каждого `i` структурные проверки (мишень непуста, площадь ≥ 4,
  помещается в поле, `S` достижима сверху) + хотя бы один сквозной прогон уровня до победы
  (`FixedSequenceGenerator`/чит).
- [ ] `flutter analyze` — ноль; тесты зелёные.

## Не входит

- **Ловушки** (1-клеточные/тонкие места как источник сложности) — эпик «Взрыв» (BACKLOG).
- Лимит зарядов взрыва и тюнинг сложности по метрикам — эпики «Взрыв»/«Плейтест-сборка».
- Полный прогон подряд и финал «корабль собран» — **Стори 03**.
- Формы деталей и раскладка силуэта — заданы в **Стори 01** (здесь только размещение, порядок,
  проходимость).

## Затронутые модули

- `lib/game_engine/data/` — `level_map` (`_devLevels`: `targetX/targetY`, порядок; вывод
  `LevelMap.objects` из дев-потока).
- `lib/game_engine/models/` — при необходимости хелпер валидации проходимости в `target_mask`/
  `level_template` (только если понадобится тесту; иначе не трогаем).
- `test/` — `level_map_test` + новый тест «каждый уровень проходим».

## Открытые вопросы к PO

1. **Условие победы и «нахлёст вне мишени»** (эпик просил подтвердить на декомпозиции).
   - **Технически (из кода `HaloCalculator.checkWin`):** победа требует, чтобы все клетки мишени
     `S` были заняты **И** весь halo `H` (8-соседи `S`) — пуст. Блоки дальше 1 клетки от `S`
     победе не мешают. Значит неровные/тонкие места закрываются **расчисткой** (взрывом)
     халопереполнения.
   - **Продуктовое подтверждение:** в этом эпике взрыв ещё **без лимита зарядов** (лимит — эпик
     «Взрыв»), т.е. проходимость опираем на неограниченную расчистку.
   - **Рекомендация агента:** оставляем как в VISION («тонкие/неровные закрывает расчистка»),
     ловушки-сложность не вводим. **Закрыть на Гейте 1:** подтвердить этот подход.
