# STORY 02 — Чит-меню (дев-сборка)

> Заполняет агент при декомпозиции эпика. PO утверждает на Гейте 1 и принимает
> на Гейте 2. Работа по стори НЕ начинается, пока секция «Открытые вопросы к PO»

**Эпик:** Мета-каркас корабля
**Статус:** на приёмке (Гейт 2) — T1–T2 готовы, все критерии пройдены с доказательствами

## Ценность

PO/разработчик может **в дев-сборке выбрать уровень, мгновенно победить и задать
состояние корабля**, чтобы **проверять любую точку игры за секунды, не проходя её руками**.

## Критерии приёмки

- [x] В дев-сборке на игровом экране есть вход в чит-меню; в релизной сборке он скрыт
  (определяется через `kDebugMode`).
  _Доказано: `IconButton(Key('cheat_button'))` под `if (kDebugMode)`; тест «В dev-сборке
  кнопка читов есть и открывает меню» зелёный. Релизная ветка скрыта идиомой `kDebugMode`
  (в тестах `kDebugMode == true`, поэтому проверяется дев-ветка + кодом сама гейтировка)._
- [x] Чит «выбор уровня»: выбрал уровень K → игра перезапускается на уровне K.
  _Доказано: тест «выбор уровня 3 → `GameScreen(levelIndex=2)`» (подпись «Level 3»)._
- [x] Чит «мгновенная победа»: тап → текущий уровень засчитан пройденным (прогресс +1,
  запускается текущий пост-победный поток — тот же, что после обычной победы, каким бы
  он ни был на момент стори). Реализуется на мета-уровне (`ProgressService` + навигация),
  движок не трогаем.
  _Доказано: `_cheatInstantWin` → `_handleWin` (единая точка с тиком) → `_onWin`
  (`advanceOnWin` + навигация); тест: 0 → 1 и открывается `LevelCompleteScreen`. `game_engine` не менялся._
- [x] Чит «установка состояния корабля»: задал «собрано N деталей» (N = 0..3) → экран
  корабля и сохранённый прогресс отражают N (через `ProgressService.setCurrentLevel`).
  _Доказано: тест «N=2 → прогресс=2 → корабль 2/3»._
- [x] `flutter analyze` — ноль; существующие тесты зелёные; читы не падают.
  _Доказано: `flutter analyze` — No issues; `flutter test` — 225 passed (+4 новых), читы
  прогнаны тестами без падений._

## Не входит

- Доступность чит-меню в релизной сборке (наоборот — скрыть).
- Правка мишеней/масок/правил укладки — ядро заморожено (VISION).
- Красивый UI — минимально функциональный список кнопок.

## Затронутые модули

- `lib/presentation/screens/` — экран/оверлей чит-меню (новый) + вход из игрового экрана.
- `lib/application/` — `ProgressService` (`setCurrentLevel`/`reset`/`advanceOnWin` уже есть).
- _Движок (`game_engine/*`) НЕ затрагивается: «мгновенная победа» имитируется на мета-уровне
  (засчитать прогресс + запустить пост-победный поток), без изменения ядра._

## Задачи

> Нарезаны при старте стори (AGENT.md п. 3). Уточнение контура: чит «состояние корабля»
> (чистый `ProgressService`, без навигации) перенесён в T1, чтобы каждая задача была
> рабочим инкрементом без кнопок-заглушек; навигационные читы — в T2.

### T1 — Вход (dev) + оверлей чит-меню + чит «состояние корабля»
- **Статус:** готова
- **Модули:** presentation/screens (`CheatMenu` + вход на `GameScreen`), application (`ProgressService`)
- **Результат:** в `kDebugMode` на игровом экране кнопка-жук открывает `CheatMenu`
  (bottom sheet со списком кнопок); в релизе кнопки нет (`if (kDebugMode)`). Чит «собрано
  N деталей» (N=0..3) → `ProgressService.setCurrentLevel(N)` → экран корабля показывает N.
- **Проверка:** в debug кнопка есть и открывает меню; тап «N=2» → корабль показывает 2;
  `flutter analyze` — ноль.

### T2 — Читы «выбор уровня» и «мгновенная победа»
- **Статус:** готова
- **Модули:** presentation/screens (`GameScreen` + `CheatMenu`), application (`ProgressService`)
- **Результат:** «выбор уровня K» → `GameScreen` перезапускается на уровне K
  (`pushReplacement`). «Мгновенная победа» → тот же пост-победный поток, что после обычной
  победы (рефактор `GameScreen`: единая точка обработки победы, переиспользуется тиком и
  читом; движок не трогаем). Прогресс +1.
- **Проверка:** тест: выбор уровня → `GameScreen(levelIndex=K)`; мгновенная победа →
  прогресс +1 и открывается пост-победный экран; читы не падают; существующие тесты зелёные.
