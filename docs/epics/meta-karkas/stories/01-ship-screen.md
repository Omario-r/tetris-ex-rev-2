**Эпик:** Мета-каркас корабля
**Статус:** в работе (T1, T2 готовы; T3 следующая)

## Ценность

Игрок может **открыть экран корабля из игры и увидеть, из каких деталей уже собран
его корабль**, чтобы **видеть свой прогресс сборки и то, что он строит что-то большое**.

## Критерии приёмки

- [ ] На игровом экране есть кнопка/иконка «Корабль»; тап открывает экран корабля,
  кнопка «Назад» возвращает в игру.
- [ ] Экран корабля показывает ЕДИНЫЙ корабль из 3 деталей-заглушек: собранные детали
  видны установленными, ещё не собранные — контуром/пусто.
- [ ] Дев-контент ограничен 3 уровнями, связка строго 1:1: пройден уровень N → деталь N
  на месте; прогресс не выходит за 3.
- [ ] Число собранных деталей = числу пройденных уровней. Чит-меню на этой стори ещё
  недоступно — проверять прохождением уровней или ручной установкой сохранённого прогресса.
- [ ] Сохранение сборки: закрыть и снова открыть приложение → экран корабля показывает то же
  число собранных деталей (через существующий `ProgressService`, ключ `current_level`).
- [ ] `flutter analyze` — ноль; существующие тесты зелёные.

## Не входит

- Авто-показ корабля после победы — Стори 03.
- Реальные 10–12 деталей и их дизайн — эпик «Контент»; здесь только 3 заглушки.
- Анимации/частицы/звук; полноценное главное меню приложения.
- Финал «корабль собран полностью».

## Задачи

> Нарезаны при старте стори (AGENT.md п. 3). Порядок = порядок выполнения:
> T1 даёт модель+пейнтер, T2 — экран+вход, T3 — тест восстановления.
> Технические решения нарезки — в «Заметках по выполнению».

### T1 — Модель корабля + ShipPainter (заглушки)
- **Статус:** готова
- **Модули:** presentation/widgets (+ модель корабля, ко-локация)
- **Результат:** `ship.dart` — корабль = список из 3 деталей-заглушек (`kShipPartCount = 3`,
  единый источник истины) + `ShipPainter(collectedCount)`: собранные детали залиты,
  ещё не собранные — контуром. Проверка: пейнтер рендерится без ошибок, `flutter analyze` — ноль.

### T2 — Экран корабля + вход из игры
- **Статус:** готова
- **Модули:** presentation/screens (новый `ShipScreen` + кнопка-иконка на `GameScreen`),
  presentation/widgets (`ShipPainter`), application (`ProgressService`, читаем)
- **Результат:** иконка «Корабль» на игровом экране → `Navigator.push` → `ShipScreen`;
  экран читает `ProgressService.getCurrentLevel()`, собрано = `min(level, kShipPartCount)`,
  рисует через `ShipPainter`; «Назад» (AppBar) возвращает в ту же партию. Проверка:
  тап по иконке → экран корабля с N деталями; назад → игра. Существующие тесты зелёные.

### T3 — Тест восстановления прогресса _(рекомендован; прототип, хрупкое — persistence)_
- **Статус:** не начата
- **Модули:** presentation/screens (widget-тест `ShipScreen` + mock `SharedPreferences`)
- **Результат:** widget-тест: `current_level = K` (mock prefs) → `ShipScreen` показывает
  `min(K, 3)` собранных деталей (проверяем K=0/1/2/3 и K>3 → 3). Покрывает критерий
  сохранения сборки. Оставлена PO (консультация 2026-07-07).

## Заметки по выполнению

- **Граница «ограничен 3 уровнями» (техническое решение нарезки).** Стори 01 реализует
  ограничение на уровне корабля-вида: корабль имеет ровно `kShipPartCount = 3` слота,
  собрано = `min(current_level, 3)` (кламп). Фактическое прохождение игры (навигация
  game→победа, число играбельных уровней) в этой стори НЕ трогается — это территория
  Стори 03 (перекройка пост-победного потока + финал-сброс) и Стори 02 (читы). Так все
  критерии Стори 01 выполнимы без правки хрупкого игрового потока. Единый источник «3»
  (`kShipPartCount`) делает будущий кап уровней в Стори 03 однострочным. Эпик делегировал
  «как — решает исполнитель» (EPIC.md, границы).
- **Где живёт модель корабля.** Ко-локация с пейнтером в `presentation/widgets/ship.dart`:
  детали — чисто-визуальные заглушки без логики движка; новых связей между модулями и
  зависимостей в pubspec не появляется (screens уже зависит от widgets и application).
- **Вход/возврат.** `Navigator.push` (не `pushReplacement`): игровой экран остаётся под
  стеком, «Назад» возвращает в ту же партию.
- **Тест-готча (для T3 и Стори 03).** Пока `GameScreen` в дереве, `pumpAndSettle()`
  зависает — его `AnimationController..repeat()` (игровой цикл) не settle-ится. В тестах
  навигации с игрового экрана использовать `pump()` + `pump(Duration)`, не `pumpAndSettle`.
