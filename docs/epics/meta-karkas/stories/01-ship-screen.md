**Статус:** не начата

## Ценность

Игрок может **открыть экран корабля из игры и увидеть, из каких деталей уже собран
его корабль**, чтобы **видеть свой прогресс сборки и то, что он строит что-то большое**.

## Критерии приёмки

- [ ] На игровом экране есть кнопка/иконка «Корабль»; тап открывает экран корабля,
  кнопка «Назад» возвращает в игру.
- [ ] Экран корабля показывает ЕДИНЫЙ корабль из 3 деталей-заглушек: собранные детали
  видны установленными, ещё не собранные — контуром/пусто.
- [ ] Дев-контент ограничен 3 уровнями, связка строго 1:1: пройден уровень N → деталь N
  на месте; прогресс не выходит за 3.
- [ ] Число собранных деталей = числу пройденных уровней. Чит-меню на этой стори ещё
  недоступно — проверять прохождением уровней или ручной установкой сохранённого прогресса.
- [ ] Сохранение сборки: закрыть и снова открыть приложение → экран корабля показывает то же
  число собранных деталей (через существующий `ProgressService`, ключ `current_level`).
- [ ] `flutter analyze` — ноль; существующие тесты зелёные.

## Не входит

- Авто-показ корабля после победы — Стори 03.
- Реальные 10–12 деталей и их дизайн — эпик «Контент»; здесь только 3 заглушки.
- Анимации/частицы/звук; полноценное главное меню приложения.
- Финал «корабль собран полностью».

## Затронутые модули

> По карте из ARCHITECTURE.md. Если модуля ещё нет — пометить «(новый)».

- `lib/presentation/screens/` — новый экран корабля (ShipScreen) + вход из игрового экрана.
- `lib/presentation/widgets/` — отрисовка корабля из деталей (адаптировать `ObjectFullPainter`).
- `lib/application/` — чтение сохранённого прогресса (`ProgressService`, уже есть).
- _Модель «корабль = список деталей-заглушек, деталь ↔ уровень» — где живёт (widget/data),
  решаю технически при нарезке задач; новых зависимостей в pubspec не планируется._
- _Ограничение дев-контента 3 уровнями: где живёт (данные `LevelMap` / константа в
  application) — техническое решение при нарезке. Если выйдет 4-й модуль — задача
  режется по правилу трёх (AGENT.md п. 3)._
