# STORY 03 — Авто-показ прироста корабля после победы

> Заполняет агент при декомпозиции эпика. PO утверждает на Гейте 1 и принимает
> на Гейте 2. Работа по стори НЕ начинается, пока секция «Открытые вопросы к PO»
> не пуста.

**Эпик:** Мета-каркас корабля
**Статус:** в работе (T1, T2 готовы; T3 следующая)

## Ценность

После сборки мишени игрок **автоматически видит экран корабля, где на место встаёт новая
деталь**, чтобы **связка «собрал мишень → прирос корабль» читалась без слов** (VISION, успех №2).

## Критерии приёмки

- [ ] После победы на уровне открывается экран корабля (переиспользует экран из Стори 01),
  а не старые экраны объекта/фрагмента.
- [ ] Только что заработанная деталь появляется с простым эффектом (scale-in); остальные — статично.
- [ ] Кнопка «Далее» ведёт на следующий уровень.
- [ ] Победа на 3-м (последнем) уровне: экран корабля показывает собранный корабль (3/3)
  и кнопку «Начать заново» → прогресс сбрасывается в 0, игра начинается с уровня 1.
- [ ] Прогресс сборки увеличивается на 1 и сохраняется (`ProgressService.advanceOnWin`).
- [ ] `flutter analyze` — ноль; тесты навигации обновлены под новый поток и зелёные.

## Не входит

- Сложные анимации/частицы/звук — только простое появление детали.
- Полноценный финал «корабль собран» (анимации, фанфары) — эпик «Контент»; здесь
  только статичный собранный корабль + кнопка «Начать заново».
- Изменение правил ядра (условие победы уже есть).

## Затронутые модули

- `lib/presentation/screens/` — `game_screen` (навигация после победы) + экран корабля из Стори 01.
  Старые `LevelCompleteScreen`/`ObjectCompleteScreen` (модель «коллекция объектов») здесь
  заменяются единым авто-показом корабля; их тесты обновляются/замещаются.
- `lib/presentation/widgets/` — эффект появления детали (адаптировать анимацию `ObjectFragmentGridPainter`).
- `lib/application/` — `ProgressService.advanceOnWin` (уже есть).

## Задачи

> Нарезаны при старте стори (AGENT.md п. 3). Технические решения — в «Заметках по выполнению».

### T1 — Навигация: победа → авто-показ корабля (Далее / Начать заново)
- **Статус:** готова
- **Модули:** presentation/screens (`game_screen` + `ship_screen`), application (`ProgressService`)
- **Результат:** `_onWin` рвётся со старых экранов на `ShipScreen` в режиме авто-показа:
  корабль с N деталями + кнопка «Далее» (→ след. уровень). На последнем дев-уровне
  (индекс `kShipPartCount-1`) — «Начать заново» → `ProgressService.reset()` → уровень 1.
  Эффект детали — статикой (анимация в T2). Старые экраны пока остаются (мёртвыми), удаляются в T3.
- **Проверка:** победа → экран корабля с «Далее»; на 3-м уровне → 3/3 + «Начать заново» → сброс;
  чит «мгновенная победа» ведёт на новый экран (обновить его ассерт). `flutter analyze` — ноль.

### T2 — Эффект появления новой детали (scale-in)
- **Статус:** готова
- **Модули:** presentation/widgets (`ShipPainter` + `revealPartIndex/revealProgress`),
  presentation/screens (`ShipScreen` — `AnimationController` в режиме авто-показа)
- **Результат:** только что заработанная деталь въезжает scale-in (0→1); остальные статичны.

### T3 — Тесты нового потока + удаление мёртвых старых экранов _(рекомендован; хрупкое — навигация после победы)_
- **Статус:** не начата
- **Модули:** presentation/screens (+ тесты)
- **Результат:** тесты: победа → экран корабля, деталей +1, «Далее» → следующий уровень;
  победа на 3-м уровне → 3/3 + «Начать заново» → сброс. Удалить `LevelCompleteScreen`/
  `ObjectCompleteScreen` и их тесты, подрезать `navigation_test` под новый поток. Оставлена PO.

## Заметки по выполнению

- **Кап дев-контента 3 уровнями (обещанное из Стори 01).** «Последний уровень» =
  индекс `kShipPartCount-1` (=2); после него — сброс и новый круг. Единый источник «3»
  (`kShipPartCount`) — тот самый, что заложен в Стори 01.
- **Переиспользование экрана.** `ShipScreen` получает режим авто-показа (именованный
  конструктор): без «Назад», с кнопкой «Далее»/«Начать заново» и подсветкой новой детали.
  Обычный (ручной) режим из Стори 01 сохраняется.
- **Мёртвый код.** После T1 `game_screen` не зовёт старые экраны; сами файлы и их тесты
  удаляются в T3 (чтобы T1 остался компактным и зелёным).
