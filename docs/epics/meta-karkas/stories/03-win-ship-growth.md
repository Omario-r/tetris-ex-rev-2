**Эпик:** Мета-каркас корабля
**Статус:** на приёмке (Гейт 2, повторно после возврата T4) — T1–T4 готовы, критерии пройдены

## Ценность

После сборки мишени игрок **автоматически видит экран корабля, где на место встаёт новая
деталь**, чтобы **связка «собрал мишень → прирос корабль» читалась без слов** (VISION, успех №2).

## Критерии приёмки

- [x] После победы на уровне открывается экран корабля (переиспользует экран из Стори 01),
  а не старые экраны объекта/фрагмента.
  _Доказано: `_onWin` → `ShipScreen.reveal`; старые `LevelComplete`/`ObjectComplete` удалены;
  тест `win_flow_test` «победа → корабль» (find `ShipScreen`) зелёный._
- [x] Только что заработанная деталь появляется с простым эффектом (scale-in); остальные — статично.
  _Доказано: `ShipPainter.revealPartIndex/revealProgress` (масштаб от центра),
  `ShipScreen.reveal` анимирует (easeOut 400мс); тест «revealProgress 0→1» зелёный._
- [x] Кнопка «Далее» ведёт на следующий уровень.
  _Доказано: `win_flow_test` — «Далее» → `GameScreen(levelIndex=1)` / «Level 2»._
- [x] Победа на 3-м (последнем) уровне: экран корабля показывает собранный корабль (3/3)
  и кнопку «Начать заново» → прогресс сбрасывается в 0, игра начинается с уровня 1.
  _Доказано: `win_flow_test` — с уровня 2 → «Собрано 3 из 3» + «Начать заново» →
  `reset()` → `GameScreen(0)` / «Level 1», `current_level == 0`._
- [x] Прогресс сборки увеличивается на 1 и сохраняется (`ProgressService.advanceOnWin`).
  _Доказано: `win_flow_test` — `getCurrentLevel` 0 → 1 после победы._
- [x] `flutter analyze` — ноль; тесты навигации обновлены под новый поток и зелёные.
  _Доказано: `navigation_test` подрезан до входа `main.dart`, поток вынесен в `win_flow_test`;
  `flutter analyze` — No issues; `flutter test` — 216 passed._
- [x] Деталь на корабле совпадает по форме с мишенью уровня (возврат PO, T4).
  _Доказано: единый источник формы `ShipParts.parts[i].mask` — используется и как мишень
  дев-уровня (`LevelMap.levelAt`), и как деталь корабля (`ShipPainter`). Тест
  `level_map_test` «levelAt(i).targetMask == ShipParts.parts[i].mask» зелёный._

## Не входит

- Сложные анимации/частицы/звук — только простое появление детали.
- Полноценный финал «корабль собран» (анимации, фанфары) — эпик «Контент»; здесь
  только статичный собранный корабль + кнопка «Начать заново».
- Изменение правил ядра (условие победы уже есть).

## Задачи

> Нарезаны при старте стори (AGENT.md п. 3). Технические решения — в «Заметках по выполнению».

### T1 — Навигация: победа → авто-показ корабля (Далее / Начать заново)
- **Статус:** готова
- **Модули:** presentation/screens (`game_screen` + `ship_screen`), application (`ProgressService`)
- **Результат:** `_onWin` рвётся со старых экранов на `ShipScreen` в режиме авто-показа:
  корабль с N деталями + кнопка «Далее» (→ след. уровень). На последнем дев-уровне
  (индекс `kShipPartCount-1`) — «Начать заново» → `ProgressService.reset()` → уровень 1.
  Эффект детали — статикой (анимация в T2). Старые экраны пока остаются (мёртвыми), удаляются в T3.
- **Проверка:** победа → экран корабля с «Далее»; на 3-м уровне → 3/3 + «Начать заново» → сброс;
  чит «мгновенная победа» ведёт на новый экран (обновить его ассерт). `flutter analyze` — ноль.

### T2 — Эффект появления новой детали (scale-in)
- **Статус:** готова
- **Модули:** presentation/widgets (`ShipPainter` + `revealPartIndex/revealProgress`),
  presentation/screens (`ShipScreen` — `AnimationController` в режиме авто-показа)
- **Результат:** только что заработанная деталь въезжает scale-in (0→1); остальные статичны.

### T3 — Тесты нового потока + удаление мёртвых старых экранов _(рекомендован; хрупкое — навигация после победы)_
- **Статус:** готова (удалены `LevelComplete`/`ObjectComplete` + их пейнтеры
  `ObjectFullPainter`/`ObjectFragmentGridPainter` и тесты; `navigation_test` подрезан;
  добавлен `win_flow_test`)
- **Модули:** presentation/screens (+ тесты)
- **Результат:** тесты: победа → экран корабля, деталей +1, «Далее» → следующий уровень;
  победа на 3-м уровне → 3/3 + «Начать заново» → сброс. Удалить `LevelCompleteScreen`/
  `ObjectCompleteScreen` и их тесты, подрезать `navigation_test` под новый поток. Оставлена PO.

### T4 — Возврат Гейта 2: деталь корабля = мишень уровня (единый источник формы)
- **Статус:** готова
- **Модули:** game_engine/data (`ship_parts` + `LevelMap`), presentation/widgets (`ShipPainter`)
- **Замечание PO:** на уровне игрок собирает одну форму (лесенку), а на корабль встаёт
  другая (прямоугольник) — связка не читается (скриншоты 2026-07-07).
- **Решение PO:** источник правды — корабль; мишень уровня должна совпадать с деталью.
- **Результат:** `ShipParts` (game_engine/data) — единый источник формы (3 маски-заглушки,
  площадь кратна 4). `LevelMap.levelAt(0..2)` берёт мишень = `ShipParts.parts[i].mask`;
  `ShipPainter` рисует те же маски. Собранное на уровне = деталь корабля. Тесты:
  `level_map_test` (совпадение), `ship_parts_test`. `flutter test` — 216, `analyze` — ноль.

## Заметки по выполнению

- **Возврат Гейта 2 (T4) — единый источник формы.** Форма детали жила в двух местах
  (заглушки-`Rect` в `ship.dart` и мишени `LevelMap`) и не совпадала. Вынес форму в
  `game_engine/data/ship_parts.dart` (`ShipParts`) — её читают И мишень уровня, И корабль.
  Данные формы лежат в `game_engine` (не в presentation), т.к. слои импортируют только вниз
  (`LevelMap` не может тянуть виджеты); новая связь `widgets → data` (ARCHITECTURE обновлён).
  `LevelMap.objects` (старая карта объектов) в дев-потоке теперь не используется вовсе —
  `levelAt(0..2)` идёт мимо неё; объекты остаются для эпика «Контент».

- **Кап дев-контента 3 уровнями (обещанное из Стори 01).** «Последний уровень» =
  индекс `kShipPartCount-1` (=2); после него — сброс и новый круг. Единый источник «3»
  (`kShipPartCount`) — тот самый, что заложен в Стори 01.
- **Переиспользование экрана.** `ShipScreen` получает режим авто-показа (именованный
  конструктор): без «Назад», с кнопкой «Далее»/«Начать заново» и подсветкой новой детали.
  Обычный (ручной) режим из Стори 01 сохраняется.
- **Мёртвый код.** После T1 `game_screen` не зовёт старые экраны; сами файлы и их тесты
  удаляются в T3 (чтобы T1 остался компактным и зелёным).
