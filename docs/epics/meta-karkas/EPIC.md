# EPIC — Мета-каркас корабля

> Цель и границы формулирует PO — сам или руками советника на консультации;
> утверждает всегда PO. Список стори заполняет агент при декомпозиции
> и выносит на Гейт 1. Статусы ведёт агент.

**Статус:** в очереди

## Цель

После каждого пройденного уровня игрок видит, как его корабль прирастает новой
деталью; корабль можно посмотреть из меню в любой момент; прогресс сборки
сохраняется между запусками игры.

## Границы

**Входит:**
- Экран корабля — статичный вид собранного на данный момент (2–3 детали-заглушки)
- Авто-показ после победы: мишень собрана → экран корабля → деталь встаёт на
  место с простым эффектом → «дальше»
- Сохранение прогресса сборки между запусками
- Чит-меню в дев-сборке: выбор уровня, мгновенная победа, установка состояния корабля

**Не входит:**
- Боевой дизайн корабля и 10–12 деталей — эпик «Контент»
- Анимации сборки/полёта, частицы, звук — только простое появление детали
- Взрыв и лимит зарядов — отдельный эпик
- Финал «корабль собран полностью» — уедет в «Контент», на заглушках не имеет смысла
- Любые изменения ядра (укладка, мишени) — заморожено по VISION

## Связь с Vision

Напрямую двигает критерий успеха №2 (игрок понимает связку «собрал мишень →
прирос кусок корабля» без туториала — через авто-показ прироста) и создаёт базу
для №3–4. Проверяет главную гипотезу плейтеста (мета компенсирует слабости ядра).
Закрывает принцип «тестируемость без прохождения» (чит-меню с первого эпика).

## Наследие прототипа (переиспользуем, не переписываем)

Ключевые части мета-каркаса уже есть в коде — при декомпозиции опираться на них,
детали в паспортах модулей:

- `LevelMap` — 16 уровней (4 объекта × 4 фрагмента), «объект» = прообраз корабля
  (`lib/game_engine/data/`). Мишени объекта 0 не кратны 4 — контент заменит эпик «Контент».
- Экраны сборки: `LevelCompleteScreen` (сетка фрагментов, анимированная установка детали),
  `ObjectCompleteScreen` (объект целиком); поток Game → LevelComplete → (ObjectComplete)
  → Game (`lib/presentation/screens/`).
- `ProgressService` — сохранение прогресса (`shared_preferences`, ключ `current_level`
  0..15; провал = повтор) (`lib/application/`).

Значит: экран корабля, авто-показ прироста и сохранение во многом собраны на заглушках —
работа эпика ближе к переиспользованию/наполнению, чем к постройке с нуля.
