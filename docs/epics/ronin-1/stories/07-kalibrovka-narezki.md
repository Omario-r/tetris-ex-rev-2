# STORY 07 — Калибровка нарезки: тумблер трёх конфигураций в чит-меню

**Эпик:** Ронин-1 — первые модули корабля
**Статус:** в работе (нарезана Продюсером 2026-10-07; порядок — вторая, сразу после 01)

## Ценность

PO может **на телефоне переключать в чит-меню три конфигурации нарезки тех же
13 деталей и собрать каждую руками**, чтобы **выбрать играбельную нарезку
пальцами, а не спором** до того, как строить на ней остальной контент.

Откуда: вводная PO 2026-10-07 (`docs/producer/INBOX.md`) — текущая нарезка
неиграбельна: деталь 68–80 клеток режется на 17–20 кусков по 3–5 клеток
(прототип «Укладки», принятый PO, — 5 кусков на 20 клеток); к концу сборки
оставшиеся куски некуда поставить, поправить частично нельзя, только
пересобирать. Разрешение PO: тумблер может выходить за числа VISION и эпика
(куски > 5 клеток, деталь < 60 клеток, сетка грубее 44×108); текущая
конфигурация в тумблер **не входит** («в неё нельзя играть»). VISION тумблер не
меняет — правку по итогам КТ-1 вносит PO. План — `docs/producer/PLAN.md`, Этап 1.

## Конфигурации

| Ключ | Название в меню | Силуэт уровня | Поле | Куски | Ожидаемо |
|---|---|---|---|---|---|
| `bigPieces` | «Крупные куски» | деталь целиком (как сейчас) | 10×14, клетка 34 | нарезка 3..5, затем слияние соседних в 5..12 | 7–10 кусков |
| `halfPart` | «Полдетали» | связная половина детали | 10×14, клетка 34 | 3..5 | ~8–10 кусков |
| `coarseCell` | «Крупная клетка» | деталь, огрублённая 2×2 | 5×7, клетка 68 | 3..5 | ~4–6 кусков |

Порядок в меню — как в таблице; **по умолчанию `bigPieces`** (в том числе в
release: прежняя нарезка неиграбельна, а чит-меню в release нет).

## Контекст для нарезки

- Генератор `slicePolyomino` (`lib/game_engine/packing/pack_slicer.dart`)
  перебирает все связные подмножества у якоря — куски > 5 клеток напрямую им
  резать нельзя (перебор взрывается). Крупные куски получаются **слиянием
  соседних** кусков обычной нарезки: покрытие сохраняется по построению.
  Алгоритм проверен Продюсером черновым скриптом на 13 деталях × seed 0..4:
  7–10 кусков, размеры 5..12.
- Огрубление 2×2 на 13 деталях даёт силуэты 5×4 / 5×5 по 18–20 клеток.
- Уровень сейчас: `LevelMap.levelAt(i)` (`lib/game_engine/data/level_map.dart`)
  → `TargetMask` размера поля 10×14; `GameScreen._loadLevel` режет его
  `slicePolyomino(_silhouette, seed: _seed)`; клетка поля —
  `_computeCellSize` с каноном `_canonicalCellSize = 34`; размер поля в
  клетках берётся из `_silhouette.width/height`.
- `FeedMode` живёт в `State` экрана — образец для чита, но конфигурацию нарезки
  нужно держать **вне** `State` (экран пересоздаётся на каждом уровне).
- Кусок `PackPiece` размер не проверяет; инвариант 3..5 записан только в
  doc-комментарии.

- **Цель:** из маски детали, конфигурации и seed получается готовый уровень —

- **Модули (≤ 3):** `lib/game_engine/packing/` (паспорт
  `lib/game_engine/packing/README.md`); `lib/game_engine/data/` — только
  чтение, и только из теста (`RoninParts`); в `lib/` модуль `packing` от
  `data` по-прежнему не зависит.
- **Что сделать:** новый файл `lib/game_engine/packing/slice_config.dart`:
  1. `enum SliceConfig { bigPieces, halfPart, coarseCell }` — порядок важен
     (порядок кнопок в меню). Doc-комментарий к каждому значению — строка
     таблицы «Конфигурации» стори.
  2. Результат:
     ```dart
     class PreparedLevel {
       final int fieldWidth;      // клетки
       final int fieldHeight;
       final TargetMask silhouette; // размера поля fieldWidth×fieldHeight
       final int targetX;           // сдвиг bbox силуэта в поле
       final int targetY;
       final int cellScale;         // 1 — клетка 34 px, 2 — клетка 68 px
       final PackSlice slice;       // нарезка silhouette (координаты поля)
     }
     PreparedLevel prepareLevel(TargetMask partMask, SliceConfig config, {required int seed});
     ```
     `partMask` — bbox-маска детали (`RoninPartDef.mask`).
  3. Общая часть: рабочая маска `work` (по конфигурации, ниже) вписывается в
     поле по центру: `targetX = (fieldWidth - work.width) ~/ 2`,
     `targetY = (fieldHeight - work.height) ~/ 2`, `silhouette =
     work.padTo(width: fieldWidth, height: fieldHeight, dx: targetX, dy:
     targetY)` (`TargetMask.padTo` в `lib/game_engine/models/target_mask.dart`).
     Нарезка — от `silhouette`.
  4. `bigPieces`: поле 10×14, `cellScale` 1, `work = partMask`;
     `base = slicePolyomino(silhouette, seed: seed)`, затем
     `mergeAdjacentPieces(silhouette, base)` — публичная функция того же файла
     `PackSlice mergeAdjacentPieces(TargetMask silhouette, PackSlice base)`,
     возвращает новый `PackSlice` (тестируется отдельно). Слияние,
     детерминированно:
     - группа = множество абсолютных клеток куска (`solution[id] + cells`);
       соседи — группы, у которых есть клетки, смежные по 4-соседству;
     - **проход 1:** по группам в порядке id; группа, ещё не участвовавшая в
       слиянии, сливается с соседом, который тоже не участвовал и с которым
       суммарный размер ≤ 10; из таких — наименьший по размеру, при равенстве —
       наименьший id. Поглощённая группа исчезает, обе помечаются
       «участвовали»;
     - **проход 2:** каждая живая группа, не участвовавшая в слиянии,
       вливается в живого соседа (любого) с суммой ≤ 12; выбор — наименьший
       по размеру, при равенстве — наименьший id; не нашлось — остаётся как есть;
     - результат — новый `PackSlice`: id 0..N-1 в порядке возрастания
       минимального линейного индекса клетки (`y*width+x`) группы; `cells`
       нормализованы (`min x == 0`, `min y == 0`), `solution[id] = (minX, minY)`.
  5. `halfPart`: поле 10×14, `cellScale` 1. `work` — половина детали: BFS по
     4-соседству по клеткам `partMask` (не поля) из клетки с минимальным `(y, x)` (строка, затем
     столбец), соседи в порядке вверх, влево, вправо, вниз; берутся первые
     `ceil(n/2)` клеток в порядке BFS (префикс BFS связен). `work` — маска по
     bbox взятых клеток. Нарезка — `slicePolyomino(silhouette, seed: seed)`.
  6. `coarseCell`: поле 5×7, `cellScale` 2. `work` — огрубление: клетка
     `(cx, cy)` огрублённой маски размером `ceil(w/2)×ceil(h/2)` есть, если из
     четырёх клеток блока `x ∈ {2cx, 2cx+1}`, `y ∈ {2cy, 2cy+1}` клетками
     `partMask` являются хотя бы 2 (клетки за краем маски не считаются);
     затем остаётся наибольшая 4-связная компонента (при равенстве — с
     минимальной клеткой по `(y, x)`), маска обрезается по её bbox. Нарезка —
     `slicePolyomino(silhouette, seed: seed)`.
  7. Тесты `test/game_engine/packing/slice_config_test.dart` (рядом с
     `pack_slicer_test.dart`): для каждой конфигурации × 13
     деталей `RoninParts.parts` × seed 0..4:
     - `silhouette` размера поля; силуэт связен; укладка кусков по `solution`
       покрывает силуэт ровно (каждая клетка силуэта — ровно одним куском, вне
       силуэта — ничем); каждый кусок связен и нормализован;
     - размеры кусков и число: `bigPieces` — 5..12 и ≤ 10; `halfPart` — 3..5 и
       ≤ 10, площадь силуэта = `ceil(n/2)`; `coarseCell` — 3..5 и ≤ 7, поле 5×7;
     - детерминизм: два вызова с одним seed дают равные куски и `solution`.
     Отдельно `mergeAdjacentPieces` на маленькой ручной маске (например,
     прямоугольник 4×3, нарезанный известным seed) — суммы ≤ 12, покрытие
     ровное.
     Если критерий размеров/числа не держится на какой-то детали — **не
     подгонять алгоритм молча**, остановиться и вернуть Постановщику (деталь,
     seed, размеры).
