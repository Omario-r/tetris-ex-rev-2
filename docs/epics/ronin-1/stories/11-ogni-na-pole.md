Игрок может **видеть на собираемой детали её мелкие приметы — голубые щели-огни,
стёкла, строб, полосу люка, шеврон и номера**, чтобы **сборка была разнообразнее и
кусок «узнавался» на месте** (доработка КТ-2, PO 2026-10-09: «щелей нет на
собираемом поле, а такие вещи добавляют разнообразия»; КТ-2 пройдена с этим
условием).

### T2 — клетка поля по D-017: вид клетки, краска поверх, свет с ореолом

- **Эталон:** `docs/design/ronin-draw.js` — `domColor(…, skipDark)`, `elemShare`,
  `elemCells`, `cellInfo`, `buildTile`, `halo`, `drawField('build')`; правила —
  DESIGN.md § «Вид клетки во время сборки».
- **Что сделать:**
  1. `PartCellColors` → добавить вид клетки: `enum PartCellKind { base, accent,
     light }`, `PartCellKind kindAt(c, r)`; `colorAt` — цвет клетки (основа —
     преобладающий, элемент — среднее его пикселей); `isDark` — по `colorAt`, как
     сейчас.
  2. `partCellColors(art, part)` — расчёт по D-017 (кеш по `part.id` прежний):
     растр детали `_samplePx` на клетку из трёх слоёв `fieldLayer`: плита —
     `hullBase` / `hullAccents` / `hullLights`, предмет — `objectsBase` /
     `objectsAccents` / `objectsLights`.
     - доля пикселей элемента в клетке (пиксели с альфой < 128 не считаются; растр
       premultiplied — как в `_dominant`): свет — яркость пикселя слоя света минус
       яркость того же пикселя основы > 0,25; цветной элемент — сумма |ΔR|+|ΔG|+|ΔB|
       слоя элементов против основы > 40; цвет элемента — среднее таких пикселей;
     - клетка элемента — доля ≥ 0,4, или ≥ 0,15 и ≥ 0,7 от доли соседа поперёк
       элемента: «горячие» клетки (доля ≥ 0,15) — если их размах по колонкам ≥
       размаха по строкам, соседи — сверху и снизу, иначе — слева и справа;
     - свет важнее цветного элемента; остальное — основа: преобладающий цвет слоя
       основы, почти чёрные пиксели (яркость < 0,03) не считаются, если их меньше
       70 % непрозрачных пикселей клетки (корзины тёмных и светлых пикселей не
       смешиваются).
  3. `paintPartCells` при `assembled == false` и заданных `colors`:
     - каждая клетка — плитка (клип `RRect` как сейчас), залитая `colorAt`;
     - у плиты поверх клеток вида `base` — краска: replay `fieldLayer(paint)` в
       масштабе детали под клипом этих плиток;
     - рельеф и заклёпки — как сейчас;
     - световые клетки рисуются **последними**: сначала все остальные плитки
       (заливка, краска, рельеф, заклёпки), затем ореол каждой световой клетки —
       `RRect` клетки с отступом 2 px и радиусом 3, заливка её цветом с
       `MaskFilter.blur(BlurStyle.normal, σ)`, `σ = 0,35 · cellSize` (эквивалент
       `shadowBlur = .7u`), альфа 0,9, без клипа (ложится на соседей); затем сами
       световые плитки (заливка, рельеф, заклёпки).
     - без `colors` (ещё не посчитаны) — как сейчас (плита — `fieldBuildPicture`,
       предмет — `backdrop` + `objectsPicture`).
     `paintPartCell` (одна клетка) — тем же путём; ореол световой клетки — до неё.
     Собранная деталь (`assembled == true`) — без изменений.
  4. Поле укладки: `PackingPainter` / `GameScreen` передают `colors` как сейчас;
     если порядок «световые последними» требует знать все уложенные клетки детали
