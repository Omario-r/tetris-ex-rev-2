# STORY 02 — Рисунок «Ронина» в Dart и экран корабля-композит

**Эпик:** Ронин-1 — первые модули корабля
**Статус:** закрыта 2026-10-08 (Гейт 2 пройден в симуляторе — раздел «Гейт 2»)

## Ценность

Игрок может **открыть экран корабля и увидеть настоящий «Ронин»: собранные
детали проступают из рисунка в полном свете, остальной борт — тонкий контур
«сюда дорастёт»**, чтобы **связка «собрал деталь → прирос кусок корабля»
читалась без слов (успех #2 VISION)**.

## Критерии приёмки

- [x] Рисунок «Ронина» портирован на Dart (`CustomPainter`, процедурно, без
      PNG-ассетов) в объёме этого эпика: **корпус** — плиты обшивки по поясам

## Не входит

- **Графика остальных секций** — гондолы (объёмы), радиатор, баки, юбка,
  сопло с факелом, маркировка «РОНИН», стыковочный люк, грузовой люк и шлюз,
  трубы: приходят в «Ронине-2» вместе со своими деталями. Плиты корпуса
  портируются целиком (это один цикл), детали на них — только до строки рендера 8. Несобранное на
  экране корабля показано контуром, картинка для него не нужна.
- **Фон рендера** — космос, планета, ореол факела: это не корабль. Фон экрана —
  `spaceBg`, как сейчас.
- **Клетка = кусок оригинала на поле укладки** — Стори 03 (здесь только точка
  входа сэмплинга).
- **Анимация встраивания и подсветка приросшей детали** — BACKLOG (вынесены из
  эпика решениями PO 2026-07-24 и 2026-07-28).
- Поток «деталь собрана» и кнопки под полем — Стори 05.

## Контекст для нарезки

- **Эталон рисунка — `docs/design/ship-render.js`** (канон, утв. PO 2026-07-12/13):
  система координат `C=24, GW=15, GH=30, OX=4C, OY=1.9C`, `px/py`, `span[]`
  (силуэт по строкам), `ROWS=27`, `BANDS`, `plates` (нарезка на плиты с
  `mulberry32(20260712)`), `plateMat`, `hullPath`, `rr`, `glowDot`. Блоки в
  границах эпика — секции «КОРПУС» и «ДЕТАЛИ ПО СЕКЦИЯМ» до маркировки «РОНИН»
  (строки рендера 0..7). Страница `ship_ronin_v4.html` — только вывод.
- **Связь сеток:** клетка рендера = 4×4 клетки сетки корабля;
  `render_x = originCol + col/4`, `render_y = row/4` (`grid.originCol = 2`) —
  формулы уже применены в `docs/design/ronin-draw.js` (`rx`/`ry`, не канон, но
  рабочий образец сэмплинга и контура борта: `drawPart`, `shipOutlinePath`).
- **Как рисовать в Dart (техническое решение — за Исполнителем/Постановщиком на
  нарезке):** JS блитит из offscreen-растра. В Dart разумно собрать рисунок один
  раз в `ui.Picture` и воспроизводить его под `canvas.save/clipPath/transform` —
  один replay на слой (собранное = один клип-путь из объединения масок), без
  асинхронной растеризации. Порисуночный клип «на клетку» — не делать: 140 replay
  на кадр.
- **Шрифтовые элементы** («V V - 7 7», «77») — в JS это `Arial Narrow`; в Dart
  системного аналога нет, а новые зависимости (шрифт-ассет) — продуктовое решение
  PO. Ориентир: рисовать `TextPainter` дефолтным `sans-serif` с подгонкой
  `letterSpacing`/масштаба под ту же ширину; расхождение по гарнитуре допустимо,
  по месту и размеру — нет.
- **Что заменяется:** `lib/presentation/widgets/ship.dart` (`ShipPainter` по
  плоским маскам) и экран `ship_screen.dart`. `ShipPainter` в его нынешнем виде
  после этой стори не нужен — экран на него больше не ссылается, а физическое
  удаление файла собрано в Стори 06 (решение PO 2026-07-29). `kShipPartCount`
  живёт в том же файле и продолжает использоваться — при выносе учесть.
  `ShipScreen.reveal`
  (авто-показ прироста с кнопкой «Далее») пока остаётся рабочим входом после
  победы; поток меняется в Стори 05.
- **Новый модуль** `lib/presentation/ship_render/` (рендер корабля + контур +
  сэмплинг) — паспорт `README.md` и правка `docs/ARCHITECTURE.md` (модуль + связи
  `screens`/`widgets` → `ship_render` → `game_engine/data` за константами сетки).

     abstract class ShipArt {
       Size get sceneSize;                 // W × H сцены, px рисунка
       Offset toScene(double x, double y); // клетка рисунка → px (как px()/py())
       ui.Picture get hullPicture;         // слой 0: корпус без предметов
       ui.Picture get objectsPicture;      // слой 1: предметы (без корпуса)
       Path get outline;                   // контур борта + гондолы (shipOutline)
       /// Форма предмета слоя 1 по id детали (`'sensor'`, `'rcs_fl'`, `'rcs_fr'`),

       Path objectShape(String partId);
