# STORY 08 — Удобство укладки: замечания PO с КТ-1

**Эпик:** Ронин-1 — первые модули корабля
**Статус:** в работе (нарезана Продюсером 2026-10-08)

## Ценность

Игрок может **искать места для кусков сам, без подсказки порядком лотка,
сбрасывать неудачную сборку одной кнопкой, листать лоток, не хватая куски, и
видеть кусок над пальцем при укладке**, чтобы **трудность сборки была в
головоломке, а не в управлении**.

Откуда: КТ-1 (`docs/producer/INBOX.md`, 2026-10-07/08). PO выбрал «Крупные
куски» (D-006) и оставил замечания: (1) нужна кнопка «Очистить поле»; (2) при
прокрутке лотка кусок сразу цепляется за палец; (3) поднятый кусок закрыт
пальцем правой руки. Узнав, что куски в лотке идут в порядке решения, PO сказал
«стало очень легко» → лоток перемешивается (D-007). Плюс баг из BACKLOG: поле
прыгает, когда лоток пустеет.

## Критерии приёмки

- [ ] **Лоток перемешан:** порядок кусков в лотке — детерминированная
      перестановка от seed уровня, не совпадающая с порядком решения
      (порядок id); при одном seed порядок всегда тот же.
- [ ] **«Очистить поле»:** кнопка в строке прогресса справа; возвращает все
      уложенные куски в лоток в исходном порядке; неактивна, когда на поле
      пусто. Есть в release.
- [ ] **Прокрутка лотка:** горизонтальный свайп по лотку, начатый на куске,
      листает лоток и кусок не поднимает; движение пальца вверх с куска —
      поднимает кусок.
- [ ] **Кусок над пальцем:** при драге кусок отцентрован по X относительно
      пальца, его нижний край выше точки касания на подъём (одна именованная
      константа). Снап-превью и укладка считаются от того же положения куска —
      превью и итог не расходятся ни на клетку. Так же для куска, который
      перекладывают с поля.
- [ ] **Поле не прыгает:** высота и ширина лотка не меняются по мере опустения;
      поле не сдвигается, когда из лотка уходит последний кусок.
- [ ] Варианты калибровки «Полдетали» и «Крупная клетка» удалены из кода и
      тестов; переключатель «Нарезка: калибровка» в чит-меню остаётся с одним
      вариантом «Крупные куски» (в него встанет колючее слияние стори 04).
- [ ] `flutter analyze` — 0; `flutter test` — зелёный; смоук
      `flutter test test/widget_test.dart test/presentation/win_flow_test.dart`
      — зелёный.
- [ ] **Гейт 2 (Продюсер, симулятор):** все пять пунктов выше руками; деталь
      собрана руками целиком; величина подъёма — на КТ-2 пальцами PO.

## Контекст для нарезки

- Уровень строит `prepareLevel` (`lib/game_engine/packing/slice_config.dart`,
  стори 07); экран — `GameScreen._rebuild()` (`game_screen.dart`), лоток —
  `trayOrder: [for (final p in slice.pieces) p.id]` — порядок id = порядок
  решения (id растут по минимальной клетке куска).
- Укладка — `PackController` (`pack_controller.dart`): `place`/`move`/`remove`,
  `remove` кладёт кусок в конец лотка. Очистки нет.
- Драг: `Listener` на куске лотка, `onPointerDown` сразу зовёт `_startDrag`
  (сырые pointer-события выбраны в «Укладке» 01: `GestureDetector.onPan` с
  горизонтальным скроллом лотка давал «кусок не идёт за пальцем»). Лоток —
  горизонтальный `SingleChildScrollView`.
- Положение куска: `_dragLiftPx = 56.0`; `_buildFeedback` рисует кусок левым
  верхним углом в `pointer - (0, 56)`; `_anchorAt` берёт клетку под этой
  точкой `floor`-ом. Высокий кусок свисает на палец.
- Высота зоны лотка в расчёте клетки — константа `_trayZoneHeight = 132.0`, а
  сам контейнер лотка — по содержимому (клетка лотка до 32 px × до 5 клеток
  высоты, стори 07) и по ширине содержимого.

### T3 — Экран: прокрутка лотка без захвата и кусок над пальцем

- **Статус:** к выполнению (после T2)
- **Рекомендованный агент:** Исполнитель (тяжёлая) · Claude (Opus,
  `ispolnitel-heavy`) — жесты: в «Укладке» уже был дефект «кусок не идёт за
  пальцем» из-за конфликта с прокруткой лотка.
- **Цель:** горизонтальный свайп по лотку листает, вертикальный — поднимает
  кусок; поднятый кусок виден над пальцем.
- **Модули (≤ 3):** `lib/presentation/screens/` — `game_screen.dart`
  (паспорт `lib/presentation/screens/README.md`).
- **Что сделать:**
  1. **Захват с лотка по направлению.** `onPointerDown` на куске лотка больше
     не стартует драг: запоминает «кандидата» в новых полях состояния
     (`int? _candidateId`, `Offset? _candidateDown`; `_dragPieceId` остаётся
     только для начатого драга). На
     `onPointerMove`, пока драга нет: смещение от точки касания `d`; когда
     `|d| > kTouchSlop` (flutter/gestures, 18): если `|d.dy| >= |d.dx|` —
     старт драга (`_startDrag` с текущей точкой); иначе — кандидат сброшен и
     ничего не вызывается: `Listener` в арене жестов не участвует, поэтому
     горизонтальный `DragGestureRecognizer` прокрутки лотка забирает жест сам
     (драг в этом касании больше не стартует).
     `onPointerUp`/`onPointerCancel` без старта — кандидат сброшен, ничего не
     уложено. Остаёмся на `Listener` (сырые события) — `GestureDetector`/
     `onPan` не возвращать (см. контекст стори). Убедиться, что прокрутку
     лотка `SingleChildScrollView` при горизонтальном свайпе с куска ничто не
     блокирует.
     Захват уложенного куска на поле (`_onBoardPointerDown`) — как сейчас,
     сразу: поле не листается.
     **После старта драга лоток не листается** (находка T2: сейчас
     горизонтальное движение зажатого пальца над лотком прокручивает
     `SingleChildScrollView` и во время драга — хелпер теста
     `dragPieceToSolution` из-за этого делает `jumpTo(0)` перед каждым
     куском). Способ — на усмотрение (физика прокрутки на время драга,
     удержание позиции и т. п.), но `Listener` куска не должен терять события.
     После правки убрать `jumpTo(0)` из хелпера — тест должен проходить без
     него.
  2. **Кусок над пальцем.** Константа `static const double _dragLiftGap =
     32.0;` (зазор между нижним краем куска и пальцем, ≈ 1 клетка — канон
     `DESIGN.md`: «офсет ~1 клетка вверх»; подбирается на устройстве)
     заменяет `_dragLiftPx`. Прямоугольник куска при драге (размер — клетка
     поля × размер куска в клетках): `left = p.x - w / 2`, `top = p.y -
     _dragLiftGap - h` (p — точка пальца). Один метод считает этот
     прямоугольник; им пользуются и `_buildFeedback` (отрисовка), и якорь
     укладки/превью (`_anchorAt` — его же зовёт `_computePreview`, поэтому
     превью и укладка меняются вместе): якорь = клетка поля под левым верхним
     углом прямоугольника, **округлением** (`(local / cell).round()`), а не
     `floor`. Кусок за пределами поля — якоря нет (как сейчас: `null`).
     То же для куска, который перекладывают с поля.
  3. Тесты (`test/presentation/game_screen_test.dart`, жесты через
     `tester.startGesture`/`moveBy`/`up`):
     - горизонтальный жест с куска лотка (например, `moveBy(Offset(-120, 0))`
       шагами) — драг не начался (нет `Key('packing_drag_feedback')`),

       прокрутка была);
     - вертикальный жест вверх с куска — драг начался, отпускание над
       известной клеткой укладывает кусок в клетку, вычисленную по формуле
       п. 2 (центр по X, низ выше пальца на `_dragLiftGap`), и превью перед

     - кусок при драге не перекрывает точку касания (нижний край feedback

     - **регрессия «непрерывный жест»** — написать: тестов на жесты указателем
