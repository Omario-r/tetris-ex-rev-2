# STORY 02 — Иконка, имя приложения, смоук на своих устройствах

**Эпик:** Готовность к плейтесту
**Статус:** не начата

## Ценность

PO может **установить и открыть игру на своих устройствах (iOS + Android) под собственным
именем и иконкой** и **пройти весь текущий контент от старта до собранного корабля без
падений**, чтобы был готовый носитель для раннего плейтеста своими силами (VISION, эпик #5
позже).

## Критерии приёмки

- [ ] Имя приложения (отображаемое на устройстве, `pubspec.yaml`/платформенные конфиги) —
  собственное, без отсылок к Minecraft.
- [ ] Иконка приложения на iOS и на Android — собственная (не дефолтная Flutter-заглушка, не
  Minecraft-стиль).
- [ ] Сборка ставится и запускается на **iOS-устройстве PO** (свободная подпись Xcode) — весь
  контент (7 уровней) проходится от старта до экрана собранного корабля без падений.
- [ ] Сборка ставится и запускается на **Android-устройстве/планшете PO** — тот же прогон без
  падений.
- [ ] `flutter analyze` — 0; локальный смоук (`flutter test test/widget_test.dart
  test/integration/golden_scenario_test.dart test/presentation/win_flow_test.dart`, см.
  ARCHITECTURE «Сквозные соглашения») зелёный перед сборкой под устройства.

## Не входит

- Раздаваемая сборка для внешних тестеров (TestFlight/APK-раздача) — вне эпика (решение PO на
  консультации 2026-07-10: только свои устройства).
- Публикация в стор, платные аккаунты (Apple $99), Play Console — product-режим, после
  плейтеста.
- Production-полиш визуала — закрывает Стори 01 этого эпика («читается как стиль», не
  арт-продакшн).
- Изменения ядра/правил/контента — заморожено VISION.

## Затронутые модули

- `android/`, `ios/` — иконка приложения, имя, конфигурация сборки (платформенная упаковка, не
  `lib/`-модуль — паспорт не требуется).
- `pubspec.yaml` — имя пакета/отображаемое имя приложения.
- Ручной прогон на физических устройствах — не код, верификация DoD.

## Открытые вопросы к PO

- **Кто физически ставит и прогоняет сборку на устройствах?** У агента в текущем CLI-окружении
  нет доступа к физическим iOS/Android устройствам PO — только веб-таргет для Preview-
  инструментов (AGENT.md п.10: веб-таргет служебный, только интерактивная проверка агентом
  через `flutter run -d web-server`, не платформа публикации). Критерии приёмки T3 требуют
  реального запуска на устройствах PO (iOS free-signing, Android планшет).
  **Рекомендация агента:** агент доводит сборку до состояния «готова к `flutter build`/
  `flutter run -d <device>`» (иконка, имя, `flutter analyze`/тесты зелёные), PO самостоятельно
  ставит и прогоняет на своих устройствах и подтверждает результат (да/нет падений) — это
  соответствует VISION («прототип гоняем на **своих** устройствах»). Если у PO есть способ дать
  агенту доступ к подключённому устройству/симулятору в этой сессии — сообщить, тогда T3 можно
  переоценить.

### T1 — Иконка и имя приложения
- **Статус:** не начата
- **Модули:** android/, ios/, pubspec.yaml (платформенная упаковка, не lib/-модуль)
- **Результат (как проверить):** `pubspec.yaml` и платформенные конфиги (`android/app/src/main/
  AndroidManifest.xml`, `ios/Runner/Info.plist`) содержат собственное имя; иконки заменены в
  `android/app/src/main/res/mipmap-*` и `ios/Runner/Assets.xcassets/AppIcon.appiconset`; сборка
  собирается локально (`flutter build apk`/`flutter build ios --no-codesign` или эквивалент)
  без ошибок.

### T2 — Локальный смоук перед сборкой на устройства

- **Модули:** test/ (прогон существующих смоук-тестов, без новых)
- **Результат (как проверить):** `flutter analyze` — 0; `flutter test test/widget_test.dart
  test/integration/golden_scenario_test.dart test/presentation/win_flow_test.dart` — зелёные.
