# RUNBOOK — установка на свои устройства (iOS + Android)

> Для PO. Цель: поставить «Voxel Voyager» на свой iPhone и/или Android-телефон
> free-signing'ом (без платного Apple Developer аккаунта, без стор-раздачи) и
> пройти весь контент от старта до собранного корабля без падений.
> Эта итерация — **только свои устройства** (эпик «Готовность к плейтесту»,
> не входит: раздача TestFlight/APK, публикация в сторы — см. стори 03 «Не
> входит»).

Предпосылки на машине разработки: установлены Flutter SDK и (для iOS) Xcode.
Проверить окружение перед стартом:

```
flutter doctor
```

Список подключённых устройств (после подключения по USB — см. разделы ниже):

```
flutter devices
```

---

## iOS (free-signing через личный Apple ID)

1. Открой **`ios/Runner.xcworkspace`** в Xcode (не `.xcodeproj` — CocoaPods
   зависимости подключены только через workspace).
2. В навигаторе слева выбери проект **Runner** → таргет **Runner** → вкладка
   **Signing & Capabilities**.
3. Включи **Automatically manage signing**, в поле **Team** выбери свой личный
   Apple ID (если его нет в списке — «Add an Account…» и войди тем же Apple ID,
   каким пользуешься на iPhone; платный Developer Program не нужен, бесплатного
   личного аккаунта достаточно для запуска на своём устройстве).
4. Если Xcode пожалуется на **конфликт bundle identifier** (`Bundle ID
   "com.example.explosiveTetris" is not available` — типично для free-signing,
   т.к. общий пул `com.example.*` занят другими бесплатными аккаунтами):
   в поле **Bundle Identifier** припиши что-то уникальное, например
   `com.<твой-никнейм>.explosiveTetris` или `com.example.explosiveTetris.<инициалы>`.
   Это чисто локальная правка для установки (Info.plist/pbxproj она не меняет
   в репозитории, если делать через Xcode UI, — если решишь закоммитить смену
   bundle id, это отдельное продуктовое решение, не делай молча).
5. Подключи iPhone кабелем к маку. На самом iPhone — «Доверять этому компьютеру»
   при запросе.
6. Запусти сборку одним из двух способов:
   - из терминала: `flutter run --release -d <device-id>` (id смотри в
     `flutter devices`);
   - из Xcode: выбери устройство в шапке (вместо симулятора) → кнопка ▶ Run.
7. При первом запуске на самом iPhone игра не откроется сразу — появится
   «Untrusted Developer». Иди в **Настройки → Основные → VPN и управление
   устройством** (VPN & Device Management), найди свой Apple ID/профиль
   разработчика, нажми **Trust**. После этого запусти игру с домашнего экрана
   вручную (повторный `flutter run` не обязателен).

**Типовые грабли (iOS):**
- Бесплатный сертификат живёт **7 дней** — по истечении iOS откажется
  запускать игру («This app has expired», значок с восклицательным знаком);
  чтобы продлить — просто пересобрать заново тем же способом (шаг 6).
- Один Apple ID free-tier одновременно держит ограниченное число App ID —
  если Xcode ругается на лимит, удали в настройках Apple ID старые
  provisioning-профили неиспользуемых тестовых приложений.
- Если `flutter run` не видит устройство — проверь, что iPhone разблокирован
  и в диалоге доверия нажато «Доверять», затем `flutter devices` ещё раз.

## Сборка с чит-меню (debug) — для контрольных точек

Чит-меню (жук в топбаре) живёт только в debug-сборке: в `--release` его нет.
Контрольные точки, где нужно переключать что-то в чит-меню, ставь так:

1. Подготовка — шаги 1–5 раздела «iOS» выше (подпись, кабель, доверие).
2. `flutter devices` → id телефона, затем `flutter run -d <device-id>`
   (без `--release` — это debug).
3. **Особенность iOS:** debug-сборку нельзя запустить иконкой с домашнего
   экрана — она стартует только из `flutter run` (или ▶ Run в Xcode). Играй
   в сессии, которую открыл `flutter run`. Можно отключить кабель после
   старта: игра работает, пока её не закроешь. Чтобы терминал отпустил
   телефон, но игра осталась, нажми в нём `d`.
4. Debug заметно медленнее release на старте и анимациях — это не дефект
   игры.
5. Нужна игра с иконки (без чит-меню) — `flutter run --release -d <device-id>`.
   Схему Runner в Xcode на Release **не переключай**: с ней перестаёт
   собираться симулятор (см. «Симулятор iOS» ниже).

Android на маке разработки сейчас не собирается (нет Android SDK) — для
Android-контроля его нужно поставить отдельно (Android Studio).

## Симулятор iOS

Debug-сборка игры на симуляторе iPhone (без подписи и устройства). Пример —
iPhone 17, UDID `1E445928-A8E2-44B1-B205-F93CFCF4AA45`; свой UDID смотри в
`xcrun simctl list devices`.

```
xcrun simctl boot 1E445928-A8E2-44B1-B205-F93CFCF4AA45   # если ещё не загружен
open -a Simulator
flutter build ios --simulator --debug                     # → build/ios/iphonesimulator/Runner.app
xcrun simctl install 1E445928-A8E2-44B1-B205-F93CFCF4AA45 build/ios/iphonesimulator/Runner.app
xcrun simctl launch 1E445928-A8E2-44B1-B205-F93CFCF4AA45 com.example.explosiveTetris
```

Интерактивно (hot reload) — `flutter run -d <UDID>`.

**Грабли:** сборка падает с «Unable to find a destination matching …
{ generic:1, platform:iOS Simulator }» (в списке только My Mac / Any iOS
Device) — значит, в схеме Runner действие **Run** переключено на Release
(`LaunchAction buildConfiguration` в
`ios/Runner.xcodeproj/xcshareddata/xcschemes/Runner.xcscheme`), а в Release по
шаблону Flutter `SUPPORTED_PLATFORMS = iphoneos` — Xcode отбрасывает
симуляторы. Верни Run → Debug (Xcode: Product → Scheme → Edit Scheme… → Run →
Build Configuration). Release-сборку на телефон делай через
`flutter run --release -d <device-id>`, схему под это не переключай (а если
переключил в Xcode — не коммить).

## Android

1. На телефоне включи **Параметры разработчика** (Настройки → О телефоне →
   7 раз тапнуть «Номер сборки»), затем в Параметрах разработчика включи
   **Отладка по USB (USB debugging)**.
2. Подключи телефон кабелем к маку. На экране телефона подтверди запрос
   «Разрешить отладку по USB с этого компьютера» (можно поставить галочку
   «Всегда разрешать с этого компьютера»).
3. Проверь, что телефон виден: `flutter devices`.
4. Запусти одним из двух способов:
   - прямой запуск: `flutter run --release -d <device-id>`;
   - сборка APK + ручная установка: `flutter build apk --release`, затем
     перекинуть `build/app/outputs/flutter-apk/app-release.apk` на телефон
     (кабелем/облаком/`adb install build/app/outputs/flutter-apk/app-release.apk`)
     и открыть файл на телефоне для установки.

**Типовые грабли (Android):**
- Телефон не виден в `flutter devices` — переустанови USB-драйвер (Windows)
  или смени USB-кабель/порт (часто «только зарядка» кабели не дают передачу
  данных); проверь, что на телефоне выбран режим USB «Передача файлов», а не
  «Только зарядка».
- При установке `app-release.apk` вручную Android блокирует «Установка из
  неизвестных источников» — разреши однократно для приложения-источника
  (Файлы/Диспетчер файлов) в диалоге, который покажет система.
- Если стоит старая версия приложения с другим ключом подписи (после смены
  окружения сборки) — установка апдейта поверх откажет («App not installed»);
  удали старую версию с телефона и поставь заново.

## Чек-лист смоука (пройти на устройстве после установки)

Цель — весь контент от старта до собранного корабля **без падений**:

- [ ] Запуск: приложение открывается на домашнем экране, без креша/белого
  экрана.
- [ ] На домашнем экране телефона иконка и подпись — **«Voxel Voyager»**
  (не дефолтная Flutter-заглушка, не «Explosive Tetris», без Minecraft).
- [ ] Кнопка взрыва (канистра-заряд) переключается по состояниям: **Готов →
  Взведён → детонация** — без зависаний/креша при взрыве.
- [ ] Собрана хотя бы одна деталь корабля → переход «Далее» на следующий
  уровень работает.
- [ ] Пройден **весь контент**: все `kShipPartCount` (7) уровней подряд, без
  падений на любом из них.
- [ ] После последней детали — счётчик показывает **N/N** (7/7) и появляется
  кнопка **«Начать заново»**; нажатие сбрасывает игру на уровень 1.
- [ ] На экране телефона (в том числе на маленьких/коротких экранах) **нет
  overflow** — HUD (кнопки, крестовина, кнопка взрыва, топбар-чип детали) не
  обрезан и не наезжает, не видно жёлто-чёрной штриховки переполнения.
- [ ] Устройство не перегревается/не подвисает в ходе всего прогона.
