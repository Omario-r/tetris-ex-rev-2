# PROJECT.md — оверлей проекта

> Проектные адаптации поверх генерик-правил из `system/`. Читается в любой роли
> вместе с правилами роли. Генерик-файлы (`system/`) локально НЕ редактируются —
> всё проектное живёт здесь. Модель синхронизации — `METHODOLOGY.md` шаблона.

## Стек и структура

- **Каталог кода** (`<каталог кода>` в правилах): `lib/`
- **Платформа:** iOS/Android (публикация). Веб-таргет — служебный (см. «Карве-ауты»).
- **Язык / фреймворк:** Flutter / Dart, без Flame (рендер `CustomPainter`, цикл
  `Ticker`/`AnimationController`, персист `shared_preferences`).

## Дизайн

> Читает Дизайнер (`system/DIZAINER.md`): платформа (выше) — чей корпус
> конвенций, класс приложения — режим их применения.

- **Класс приложения:** игра — визуальный язык кастомный (канон —
  `docs/DESIGN.md`), конвенции платформ действуют только в системной зоне:
  safe area, back-жест Android, шторки/пермишены, ориентация.
- **Целевые устройства / брейкпоинты:** телефоны PO (iOS/Android), портрет;
  эта итерация — только свои устройства (см. эпик #4).
- **Особенности:** тёмная тема поля; риск — тёмные материалы (графит/gun-metal)
  на тёмном фоне могут сливаться на экране телефона, палитру не осветлять
  заранее (решение PO), снять риск на плейтесте.

## Гейт качества

- **Линтер** (DoD п. 1): `flutter analyze` — ноль ошибок и предупреждений.
- **Тесты:** `flutter test`
- **Смоук-тест / запуск проекта:** `flutter run`; сквозной смоук —
  `flutter test test/widget_test.dart test/integration/golden_scenario_test.dart test/presentation/win_flow_test.dart`
  (подробности и карта модулей — `docs/ARCHITECTURE.md`).

## Ростер и бэкенды

Роли и уровни — `system/ROSTER.md`. Claude-бэкенды заведены в `.claude/agents/`:
`ispolnitel` (Sonnet), `ispolnitel-heavy` (Opus), `critic` (Haiku). Постановщик и
Советник — Opus (модель главной сессии выбирает PO). Спавн Исполнителя/Критика —
явный, по команде.

Внешние бэкенды (overflow при лимитах Claude, параллель): **Cursor Composer 2.5
fast** (средний тир) и **Gigacode** (слабый тир, бесплатен; узкий допуск — см.
`system/ROSTER.md`). Хендофф — готовый промпт-запуск в ТЗ задачи (канонический
шаблон — `system/HANDOFF.md`); приёмка —
три ступени (ре-ран `flutter analyze`/`flutter test` → пост-критик `critic` на
диффе → возврат находок агенту), протокол — `system/ROSTER.md`. Gigacode обкатан
на gotovnost/01 T2; обкатка HANDOFF-цепочки — на T3.

## Карве-ауты правил

- **Новые зависимости** = добавление в `pubspec.yaml` — продуктовое решение
  (эскалация PO).
- **Веб-таргет** (`web/`, добавлен `flutter create --platforms=web .` с разрешения
  PO 2026-07-08) — служебный, только для интерактивной проверки агентом через
  Preview-инструменты (`flutter run -d web-server` + браузерный клик/скриншот).
  НЕ платформа публикации (VISION: iOS/Android): игровую логику в него не
  переносить, веб-специфичный код в `lib/` не тащить.
